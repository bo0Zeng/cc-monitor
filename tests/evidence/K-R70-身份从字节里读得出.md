## §C 做了什么 —— 三条都长在**二进制自己身上**，同源于 `BUILD_ID`

### C-1 跑不动它的人：扫字节（`CC_MONITOR_BUILD_STAMP`）

`remote-daemon-proto/src/main.rs`：`BUILD_STAMP_OPEN` / `BUILD_STAMP_CLOSE` 两个界标
（**闭集唯一住址**）＋ 一段 `const fn` 编译期拼出来的
`#[used] #[no_mangle] pub static CC_MONITOR_BUILD_STAMP: [u8; BUILD_STAMP_LEN]`。

🔴 **为什么必须是 `static [u8; N]` 而不是 `&str`** —— 这是本件的支点。
`build.rs::embed_daemons` 的头注逐字记着当初为什么选了旁挂清单：
「编译器可把 BUILD_ID 优化成立即数指令（字符串在字节里**不连续**），运行时 `bytes_contain`
启发式会误拒正品二进制」。**那句话对当时那个被测对象是真的。**
一个带地址、被 `#[used]` 钉住的 `static` 数组拆不成立即数：它有地址、要进 `.rodata`、字节按定义连续
⇒ 「扫字节问身份」从一条启发式变成一条**结构性成立**的事。

现打（09-12，沙箱，独立小工程 `scratchpad/kr70-stamp-probe`，`profile.release` 带 `lto = true` / `strip = true`）：
release 壳与 debug 测试壳**两侧都扫得出，且恰好一处**。
⚠ 那是一次**实验**，不是常驻判据；常驻的那条是 `build.rs`（内嵌任何载体前扫不出就 panic）。

### C-2 跑得动它的人：`--ccm-probe` 多吐一行 `build=<BUILD_ID>`

`control/ccm/mod.rs::probe_output`。它与 `version=`（CLI 契约版本 `5`）**是两个问题**：
前者答「你是哪一次构建」，后者答「你认得哪些参数」。
monitor 侧 `ccm_probe.rs::parse_probe_output` 接住它，落进 `CcmProbeResult.build`
（`#[ts(optional)]` ＋ `skip_serializing_if` ⇒ 生成的 TS 是 `build?: string`，前端零改动）。

### C-3 旁挂那份 `.build_id` **退役**

- `build.rs` 两条内嵌路（`embed_daemons` / `embed_native_daemon`）**不再读它**，也不再对它
  `rerun-if-changed` ⇒ 动那份文件既不触发重建、也改不了身份。
- `release.yml` **不再写它**（`Stage binaries` / `Stage native daemon`），
  `Place + verify embedded daemons` 改成**读二进制的字节找戳**，Release 资产也不再附它。
- `sftp.rs` 的见证布尔 `id_from_manifest` 删掉（它见证的是「一份清单在不在」），
  换成部署出门前**无条件**跑一遍 `bytes_carry_build_stamp`。
- ⚠ **`cc-monitor-native.target` 留着**：它答的是「给哪个平台编的」，不是「你是谁」——
  那个事实今天确实只能靠旁边这一份（文件名里没有 triple）。**如实登记为同族剩余。**
- ⚠ **远端落点那个目录级 `.build_id`（`sftp::marker_path`）也留着**：它记的是「我们往这台机器上
  部署过什么」，是**部署状态**不是**载体身份**；运行期由 `hello_verdict` 兜底（件文件 `§0d` 逐字不许碰）。
  **同族剩余，见 `§E`。**

### C-4 `version = "0.0.0"`：选了件计划的路 ②（明写刻意 ＋ 判据钉住真身份住址）

代价逐字写在 `remote-daemon-proto/Cargo.toml` 那一行上方与
`build_id_guard::the_crate_version_is_deliberately_zero_and_the_real_identity_has_a_home` 的头注里：

- **路 ① 没选**：那道检查比的是「四处 == tag」，而后端换不换由**行为变没变**决定
  （`BUILD_ID` 的 bump 纪律，`SUBCOMMAND_HISTORY` 就是它的账本），不由发版节奏决定。
  绑上 tag ⇒ 后端从此有两个版本号，谁都不是权威 —— 那正是 `K33` 在身份这一维要避开的东西。
- **路 ② 的代价也如实写**：后端的身份不出现在 `cargo metadata` / `Cargo.lock` 那一面。
  今天没有任何消费者走那条路（本 crate 不发布、不被别的 crate 依赖），
  ⇒ **已知且今天为空**的代价，不是漏。
- `release.yml` 的版本一致性那一步补了一段：**第五处刻意不参加，而它从此被点名核过**
  （`version` 必须逐字 `0.0.0`，且 `const BUILD_ID` 必须抠得到）。

### C-5 `BUILD_ID` bump：`p2e-dial` → `p2f-build-stamp`

理由写在 `main.rs` 的版本谱系里：在此之前**已部署的旧 daemon 既没有戳、也答不出 `build=`**
⇒ 它必须被判 stale 换掉，否则「问得出它是谁」这条性质在已部署的机器上永远为假。
⚠ 子命令集**一条没动** ⇒ 指纹不变 ⇒ `SUBCOMMAND_HISTORY` **不追加行**（那张表记的是子命令集的历史）。

## §E 没做到 / 判不了的（逐条写清缺什么才判得了）

1. **musl 交叉产物里那个戳没实测过。** 沙箱没有 zig / musl 工具链
   （`build.rs` 那段头注自己记着 aarch64 还要一个 C 交叉编译器）。
   本件只在**本机原生 release（`lto` + `strip`）** 与 **debug 测试壳**两种形态上实测过戳还在。
   缺什么才判得了：一台能跑 `cargo zigbuild --target *-unknown-linux-musl` 的机器，
   编出来之后 `grep -ao '<<ccm-build-id:[^>]*>>'` 一下即可。
2. **`release.yml` 的改动一次都没在 CI 上跑过。** 本件动了 4 处 CI 步骤（含一段新的 PowerShell
   `[System.IO.File]::ReadAllBytes` + `Latin1` 子串搜索）。它们由
   `sftp::the_release_pipeline_stages_every_arch_that_build_rs_embeds` 与
   `local_backend::the_two_carriers_are_copies_of_one_build_with_nothing_rebuilt_between`
   在**文本层**守着，**没有任何东西真跑过那几行 pwsh**。缺什么才判得了：一次 tag 发版（或一次
   手工触发的 workflow run）。⚠ 「发版红是最贵的红」，这一格请 PM 心里有数。
3. **载体② 的替身不是真 musl 二进制**（`§A` 已写）。它证的是「`build.rs` 那条路能从字节里问出身份」，
   **不证**「真发版那两份 musl 产物里戳也在」——与第 1 条同一格。
4. **`cc-monitor-native.target` 与远端落点的 `.build_id` 两份旁文件仍在**（`§C-3` 已逐条写明理由）。
   前者答的是平台不是身份；后者是部署状态、且件文件 `§0d` 逐字不许碰 `hello_verdict` 那条兜底。
   ⇒ **同族剩余，不是本件的漏**，但它们是下一拍可以问的题。
5. **本件没有给载体③（`binaries/`，装机那份、解析次序里第一个被采用的）加构建期身份校验。**
   它今天的身份来源是 `--ccm-probe` 的 `build=`（跑得动它的人问得出），运行期仍由
   `hello_verdict` 兜底 —— 那条边界 `K-R68` 写清过，件文件 `§0d` 逐字要求保留。
   要给它一道**构建期**闸，得在 `resolve_beside_this_exe` 那条启动路上读一次几 MB 的文件或起一次进程，
   两样都要先算清代价 ⇒ **本件不自批**，留给 PM。
