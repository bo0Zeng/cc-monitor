## 2. 主表 —— 各 class 的相对误差分布

口径：`|估值 − 真高| / 真高`。
- **估值** = 浏览器实际用的那个数：`Math.max(24, round(estimateStreamNodeHeight(el)))`；估不出高的按 CSS 兜底 `120`。
- **真高（content-box）** = `getBoundingClientRect().height − padding − border`。
  取 content-box 是因为 §3 实测 `contain-intrinsic-size` 就是 content-box。
- **真高（border-box）** 一栏比的是「估值**实际占掉的位置**（= 估值 + padding + border）vs 卡的真实外框」——
  这是它对 `scrollHeight` 的真实贡献。

### 去掉之前它在干什么

83 张卡里 **13 张**被它顶起来（第二轮改完常数之后；第一轮只有 2 张）：

| 卡型 | 张数 | 估值 | 旧地板下写进 style | **今天写进 style** |

另两条停在 29.1% 而不是 ~2%。**「改常数」与「改地板」是同一件事的两半。**

### 🔴 为什么是"去掉"，不是"降到 17"

三条理由（逐条有读数，原文在 `S22-floor-readings.md`）：

1. **全局地板构造上不可能对。** 300 张细条卡的风暴场景里，「太小」与「太大」**都有害**：
   `0px` 总高偏 −28.5%/−50.3%、滚动条抖 2335/4114px、Chromium 跳转落点差 **+1535px**；
   `24px` 总高偏 **+20.5%/+23.8%**、抖 1683/1946px。而正确值**逐 class 不同**
   （content-box 真高 min：retry 17.05 · slash/bash-input 18.59 · user 21.69 · … · api-error 49.38）
   ⇒ 一个数管九个 class，必然对某些 class 错 —— 今天就错着四个。
2. **按 class 分档 ＝ 把常数抄第二遍。** class 判定整套住在 `estimateStreamNodeHeight` 里，
   而 `applyIntrinsicSize` 只拿得到 `HTMLElement` ⇒ 分档要在它里面**再做一次 class 判定**，
   同一份知识两个住址，正是「加新卡型漏改一处 ⇒ 静默落回兜底」那个病的复发形状。
3. 🔴 **它防的那件事应该出声，不该静默夹取。** `Math.max` 把「估值荒谬地小」**抹平了**
   ⇒ 估算器真坏了也没人会发现。而它自陈防的两件事都是空集：
   `0` 不可达（空/纯空白正文 `renderMessage` 根本不建卡）、负值不可能（各支全是非负项相加），
   就算真写了负值浏览器也**丢弃整条声明**落回 CSS 的 `auto 120px` —— 是**虚高，不是塌陷**。

**⇒ 保险职责搬到判据层**：`tests/scale2-height-truth.vitest.ts` 立了 **F1**
「每个 class 的 `estimateStreamNodeHeight` 最小值 ≥ 该 class 登记的常数」。
**地板掩盖估算器坏掉；F1 逮住它。** 变异 M11（retry 17 → 5）与 M12（`SUMMARY_H` 38 → 12）
当场红 —— 机检过，不是声称（§6）。
