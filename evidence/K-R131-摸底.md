## §2 四处对不上（派工单点了三处，现打是四处）

### 甲 · 同一份输出里 S1 的目标既是「1」又是「空」〔派工单点名〕

`FRONTEND_GOAL_PER_GROUP = 1` 是**一个标量、五组共用**；而 `FRONTEND_PIN["S1"]` 第三栏
逐字「S1 收完远端半那一拍改这一行（**目标：空**）」。⇒ 两处住址，互相打架。
★ 这正是本区自己命名的最贵那条病「**数与名单不同句**」，今天长在治这条病的尺子上。

### 乙 · 算术不闭合：每组 1 × 5 组 = 5 个名额，而全盘写 3〔派工单点名〕

**根因不是算错，是「组」与「处」被当成了同一个东西。**
S1–S5 是**五件**（按写区不相交切），①②③ 是**三处**（按用户看到的地方切）。
两者不是一一对应：`SPLIT_GROUPS` 现打 S1 = ①-远端半 · S2 = ①-本机半 · S3 = ①-account 半 ·
S4 = ② · S5 = ③ ⇒ **① 一处装着三件**。
⇒ 五组目标的并集本来就该小于「5 个名额」，**5 ≠ 3 不是矛盾，是「组≠处」没写下来**。

### 丙 · S1 与 S3 今天「现打 1 == 目标 1」，照判据今天就能签收〔派工单点名〕

现打（沙箱，量于 `9c9c68b`）：`S1 1/1` · `S3 1/1`。而 `K-R117#§3-3` 的收工判据逐字是
「该件那一组的前端落点数**恒等于 1**」⇒ 照字面两件今天都达标。
**裁定见 §3**（结论：S1 真达标，S3 不达标 —— 而这个差别用「1」这个数**根本表示不出来**，
只有名单表示得出来）。

## §4 那两份「有调用形状、但不是一处入口」

**`src/ccm-probe.ts`** —— 整份 90 行，逐字是 `probe_ccm_cli` 的**按 origin 的 5 分钟 TTL 缓存**；
模块头注第一句逐字「`renderLaunchCommand`（`remote-launch-run.ts`）据此决定某个 origin
走 CLI 渲染器还是兜底渲染器」。**用户界面上没有这一处**，它也不装任何东西。
把它并进设置里的某个分节 = 让底层渲染链去 import 一个 UI 模块。
⇒ 它**永远**会留在 `§S5d` 的落点名单里，而**永远不该**被算成一处安装面入口。

**`src/views/inbox-view.ts`** —— 它是收件箱**编辑 overlay** 的保存按钮，调 `write_skill_file`。
🔴 **而 `write_skill_file` 装不了 skill**：`src-tauri/src/skill_host.rs:300` 起的
`resolve_editable` 第一刀逐字是 `let real = requested.canonicalize().map_err(…)`，
错误串逐字「解析路径失败（**文件必须已存在**）」⇒ 它只能改一份**已经装好的** skill 的
白名单内文件，**建不出新文件**。
⇒ `CAP_ARCHIVE["skill.inbox"]` 那一格的依据逐字「写侧（`write_skill_file`）是往用户项目里
装东西」**现打是假的**。
**本件不改它**（`K-R117` 已签收，`[J5]` 不许事后改）⇒ **退回 PM**：订正之后
`skill.inbox` 写侧落「非装面」⇒ 人群 22→21 · S5 收 6 条 · 这一行豁免可以撤，

## §5 `KR131D2` 裁定 —— S1 与 S3，理由落在「用户看到的入口该长什么样」

### S1 ⇒ **已达标，前端这一半不用做**

- 「装后端到某台机器」本质是**对某一台机器**的动作 ⇒ 入口该跟着机器走。
  UI 侧这一处**今天已经存在**：`src/settings/panel.ts` 的 `buildMachineTabs` 把机器页切成
  「连接 / 组件 / 账号 / 工具」四栏，**组件栏**就是 `MachineCard` 拆出来的那一半。
  四条远端装口今天就住在那里 —— **它已经在 ① 该在的地方。**
- 🔴 **「目标：空」讲不通**：R63 要的是「收成一处」，**不是「取消入口」**。
  把 S1 的落点降到空 = 用户再也没有地方部署远端后端，与 `K27`
  （部署是产品的一部分，由客户端做）直接冲突。⇒ **那句散文是错的，本件把它删掉。**
- ⚠ **但 S1 这一件不是没活**：后端那一半（`sftp.rs` 四条并进统一装口）仍在；
  而且 S2/S3 要把它们的入口**搬进** `machine-card.ts` ⇒ S1 收工时这一栏的份数仍是 1，
  **内容会变**。这正是「钉名单不钉份数」买到的东西。

### S3 ⇒ **没达标，前端这一半要做** —— 而「1」这个数看不出来

- 现打 1 份，目标也是 1 份，**但不是同一份**：今天在 `accounts-section.ts`，该在 `machine-card.ts`。
  🔴 **「恒等于 1」这条判据对 S3 是瞎的** —— 搬与不搬它都给 1。这是本件把目标从
  **数**换成**名单**的第二个理由（第一个是甲那处打架）。
- **理由落在入口上**：今天用户要装账号隔离，路径是「设置 → 机器 → 某台机 → 账号栏 →
  看到空态 → 一键部署 cc-acct-iso」（`accounts-section.ts:660` 那颗按钮逐字
  `mkBtn("一键部署 cc-acct-iso")`）。而装后端走的是同一台机的**组件栏**。
  ⇒ **同一台机器上「装东西」这件事今天有两个入口，按「装的是哪个组件」分。**
  R63 裁定三逐字点名**「不许再按『… 装账号隔离』这样按实现分」** —— 它就是被点名的那一个。
- ＋ `R75`〔用@09-14「account 进后端」〕已把 acct-iso 归 ①；`K15`/`K35`/`K36`
  （本地 = 不走 ssh 的远端 · 没有「没有后端」这回事 · 两份后端逐字相同）
  ⇒ 「这台机器上装了什么」该是**一张表**，不是三个抽屉。
- 账号栏留一句指路（「这台机还没装账号隔离 → 去组件栏」），**不带命令调用 ⇒ 不算落点**。
