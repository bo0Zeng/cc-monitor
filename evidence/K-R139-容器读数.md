## 二 · `.deb` 里到底有什么（装之前先看包）

`dpkg-deb -f` / `dpkg-deb -c`，跑在一个 `--network none` 的一次性 `ubuntu:24.04` 里（宿主不解包）。

```
Package: cc-monitor
Version: 3.8.0
Architecture: amd64
Installed-Size: 51961
Depends: libwebkit2gtk-4.1-0, libgtk-3-0
Description: Claude Code CLI 的只读输出渲染窗口
 …… 完全只读、零侵入。Windows 11 / 10。
```

落盘的可执行文件**恰好两个**（`dpkg-deb -c` 全部条目里 `usr/bin/` 下的）：

| 路径 | 字节数 |
|---|---|
| `usr/bin/monitor` | 42920728 |
| `usr/bin/cc-monitor-remote` | 10222432 |

### 🔴 现打逮到的三条，先摆在这里（都不改代码，见 `§7` 立件建议）

1. **包里没有任何一个叫 `ccm` 的文件。** 分母 = `dpkg-deb -c` 的全部条目。
   ⇒ **光装 `.deb` 不可能让 `ccm` 出现在 PATH 上** —— `ccm` 是 app **跑起来之后**
   由 `install_local_ccm_entry`（`src-tauri/src/backend/control/local_backend.rs:1657` 的调用点）
   放进 `~/.cc-monitor/bin/` 的。
2. **`Description` 末句逐字「Windows 11 / 10。」** —— 这是一份 **Linux `.deb`** 的包描述。
   用户 `apt show cc-monitor` 会读到「这软件是 Windows 的」。
3. **包里那份 `cc-monitor-remote` 与发版单独放出来的 `cc-monitor-remote-x86_64` 不是同一份**
   （10222432 B vs 7573832 B；后者是 musl 静态的远端那份）。
   ⚠ 这**不一定是缺陷**（`K25` 逐字：一份代码，每个平台一份原生后端），
   但「两份后端逐字相同」（`K36`）这句话在**字节层面**上现打是**不成立**的 —— 它说的是源码同一份。
