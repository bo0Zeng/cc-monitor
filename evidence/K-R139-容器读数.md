## 三 · 台架与隔离（用户逐字「记得隔离好」的落地）

台架住 `e2e/local-backend-container/`，照 `e2e/weak-net/` 的形状：
`Dockerfile` · `build-image.sh` · `guard-run-netns.sh` · `rig.sh`。

### 3.1 🔴 网络策略：**自建 `--internal` 网络**（我裁的，理由三条）

| 选项 | 为什么没选 / 选了 |
|---|---|
| `--network none` | 没选。它用的是 docker **预置**的 `none` 网络：什么都不用建，也就什么都不用删 ⇒ 收尾那条「自建网络跑完没了」会变成**空真**（闸死了照样绿）。 |
| 放开出网（默认 bridge） | 没选。那就不再是「隔离好」了。 |
| **自建 `--internal` 网络** | **选了。** 网络对象真的被建出来、又真的被删掉（收尾那格有分母）；`--internal` 之下**没有出网**。 |

🔴 **「没有出网」是量出来的，不是声称的**（`P2` 那一格）：

```
容器出不了网（实得 bash: connect: Network is unreachable
bash: line 1: /dev/tcp/1.1.1.1/443: Network is unreachable
rc=1）
```

⚠ **代价如实写**：`--internal` **测不到中转的上游那一跳**（relay / 远端部署 / 拉取）
⇒ 那几格本轮**没测**，见 `§7`。

### 3.2 镜像里预装依赖、`.deb` 不进镜像（两件事分开量）

`Dockerfile` 预装 `libwebkit2gtk-4.1-0` / `libgtk-3-0`（= `.deb` 的 `Depends` 逐字）
＋ `xvfb` / `dbus-x11`（起 app 用）＋ `procps` / `iproute2`（量具）。
**刻意没装 `gcc`** —— Debian 系上 `/usr/bin/cc` 是 C 编译器的软链，装了它
`command -v cc` 会**恒真**，那会是一次靠环境恒真的假读数。

`.deb` 与 `monitor` **不进镜像**，跑的时候 `docker cp` 进去（进了镜像就把「测的是哪一版」焊死了）。

### 3.3 宿主上写了什么 —— **一个字节都没写**

`rig.sh` 收尾那六格（**跑完现打，全 PASS**）：

PASS 容器跑完没了 · PASS 裸容器跑完没了 · PASS 自建网络跑完没了

⚠ `K-R136` 那条已知假红（加速网卡 VF 热插拔）**本机没撞上** —— `ip link` 逐字相同。

## 五 · 🔴 `KR139D2` —— `R80` 的 POSIX 那一臂判成：**半通**

### 5.1 `R80` 那条预判逐字（住 `DECISIONS.md#R80` 第二节）

> `ccm` 入口落 `~/.cc-monitor/bin/`（`install_local_ccm_entry` 逐字「不碰 PATH」），
> 而写进用户 rc 的别名块（`shared/ccm-aliases.sh`）**只把 `~/.local/bin` 加进 PATH**，
> 第 3 行还写着「唯一实现在 `~/.local/bin/ccm`」
> ⇒ **预判：干净机器上 `ccm` / `cc` / `cct` 全是 command not found。**

### 5.2 实敲（`P8`：把产品那段 rc 片段按产品的围栏装进 `~/.bashrc` 之后）

| 名字 | `command -v`（新 shell，`bash -lic`） | **真敲一下** |
|---|---|---|
| `ccm` | **NOTFOUND** | `rc=127` |
| `cc` | **FOUND `cc`**（shell 函数） | `rc=127` |
| `cct` | **FOUND `cct`**（shell 函数） | —（同族，函数体同样调 `ccm`） |

装完片段之后的 PATH：`/home/tester/.local/bin:/usr/local/sbin:…`
—— **`~/.local/bin` 真的被加进去了，而那个目录压根不存在**；
`ccm` 在 `~/.cc-monitor/bin/`，**没被加**。

### 5.3 判决：**半通**（三选一里的第三种，不往前两种里塞）

- **结论那一半 —— 证实**：用户**一个名字都用不了**。`ccm` 找不到，`cc` / `cct` 敲下去 `rc=127`。
  `R80` 担心的那件事**真的发生了**。
- **字面那一半 —— 证伪**：`R80` 说「`ccm` / `cc` / `cct` **全是** command not found」，
  而现打 **3 个里只有 1 个**是。`cc` / `cct` 是**片段自己定义的 shell 函数**
  ⇒ `command -v` 对它们**恒真**。

🔴 **为什么这个差别值钱，而不是咬文嚼字**：
任何「用 `command -v` 探一下装好没有」的诊断，在这台机器上会对 `cc` / `cct` **报绿**，
而它们**是坏的**。⇒ 这是一个**假绿面**，不是一句措辞问题。
（`K-R129` 那轮用的 `which` 只认 PATH 上的文件，**看不见**这一档；本轮换 `command -v` 才逮到。）

### 5.4 ★ `K-R135` 的 `KR135D3` 从「推理」变成「有依据」

现打钉死：`shared/ccm-aliases.sh` 第 **14** 行（逐字
`case ":$PATH:" in *":$HOME/.local/bin:"*) ;; *) export PATH="$HOME/.local/bin:$PATH";; esac`）
加的是 `$HOME/.local/bin`；而本机真落点是 `$HOME/.cc-monitor/bin`（容器里实打：`ccm` 就在那儿）。
**同一份 snippet 本机与远端共用，而两边落点不同 ⇒ 只可能对其中一边是对的。本轮证明它对本机这边是错的。**
