### C-4 读数三 · **`BUILD_ID` 是手 bump 的常量，不是派生的** ⇒ 「同 `BUILD_ID`」不蕴含「同字节」

（量具 `§5`，量于 B 树的 git 全历史）

  · 改过 `remote-daemon-proto/src/` 的提交数 = **318**（`git log --format=%H -- remote-daemon-proto/src | wc -l`，含只改注释 / 只改测试的）
  · diff 里动过 `^const BUILD_ID` 那一行的提交数 = **32**（`git log -G '^const BUILD_ID' -- remote-daemon-proto/src/main.rs`）

🔴 **诚实边界**：这两个数**不许相减当成「漏了 286 次 bump」** —— 只改注释 / 只改测试的提交本来就不该 bump，
而「哪些改动该 bump」这个分母**没人数得出**。这两个数买到的只有一件事：**`BUILD_ID` 不是派生量**。

⇒ 而**自陈漏过 bump** 的提交（提交信息里逐字承认的），逐条点名（计数 **2**，分母 = 上面那 32 条 bump 提交的提交信息，**人读判定，不是脚本语义**）：

  · `05b0e79` 2026-08-05 `fix(F02): 指纹此前只覆盖一半命令面 —— 补上通道那半并结清一笔欠了三天的 bump（audit-0805 E4/E11）`
  · `93b0f7a` 2026-07-30 `P7 文档收口 + E34 结案 + 补上 P5 漏掉的 BUILD_ID bump（zero-poll-liveness 收官）`

⇒ 结论（**这一条是读数支撑得住的**）：三个载体的 `.build_id` 清单**都从同一处抠**
（`release.yml:167` 逐字 `BUILD_ID=$(grep -oP 'const BUILD_ID: &str = "\K[^"]+' remote-daemon-proto/src/main.rs)` · `:224` 与 `:310` 各一条同义的 `Select-String … 'const BUILD_ID: &str = "([^"]+)"'`）
⇒ **它们的清单永远互相一致，而这份一致不证明字节一致** ——
一次「改了 daemon 源码但没 bump」的发版，三份清单会齐刷刷地说同一个旧名字。
`build.rs` 那几条 panic 拦的是**盘上那份二进制与源码常量对不上**，
**拦不到**「源码变了而常量没变」。

### C-6 🔴 第 2 问的答案（一句话 + 它的射程）

**答**：
  · ① 与 ③ 在**官方发版路径**上是**同一次 `cargo build` 的同一个文件的两份拷贝**（`§B-4` 的行相邻，中间无重编）⇒ **同源，而且是最强的那种同源**。
    ⚠ **但这件事今天没有任何断言守着** —— 靠的是 `release.yml` 里两步挨着，**改一次那个文件就没了**（`§C-3` 表里「谁在校验」那一列，③ 那格是空的）。
  · ② 与 ①③ **结构上不可能同字节**（不同 target / 工具链 / runner），这正是 `K25` 裁的形状。它们的同源只能是**同源码提交 + 同 `BUILD_ID`**，由「两个 job checkout 同一个 tag」保证。

  3. 跑一次 cargo：宿主警告应从 **75 回到 74**（`R25` 裁定二记的数）。**这是这次删除的唯一读数**，
     ⚠ 而它**是那一刻的快照**，引用前重打。

## §G 判不了的（逐条写清**缺什么才判得了**）

  1. **载体① 在 Linux 发版路上缺席，是缺陷还是排期？** —— `§B-1` 那条读数（`native-daemon` 只在 `build-windows` 里）是硬的，
     但 `K32` 逐字「先做 Windows 前端 + Linux 后端，Linux 前端往后排」⇒ 它可能是**有意的**。
     **缺什么才判得了**：一句「Linux 的裸 `monitor` 该不该带本机后端」的产品判断。那是 PM / 用户的格。
  2. **删 `RemoteHomeRelative` 会不会被 `structural_scan` 点名那 8 处散文** —— **缺什么才判得了**：
     在沙箱里跑一次 `cargo test structural_scan`。本轮零产品代码 + 不在宿主跑测试（`R21`）⇒ 没跑。
  3. **①③ 在真发版里是不是真的逐字节相同** —— `§B-4` 证的是**配方**（两步之间无重编），不是**产物**。
     **缺什么才判得了**：一次真发版 run 的两份产物的 sha256，或在 `release.yml` 里加一步现算对拍。
     ⚠ 后者是产品代码，不在本件写区。
  4. **「三者是同一次构建」这句话对 ② 到底该怎么说** —— 我给的是「同源码提交 + 同 `BUILD_ID`」。
     **缺什么才判得了**：`K25` 那句「同一个二进制的射程是同一平台内的两种承载」要不要在闭集的语汇里显式化
     （即：闭集要不要有「平台」这个维度）。那是形状裁定，归 PM。
  5. **`config_surface` 那一页要不要多一列「哪个载体」** —— 这一页是给用户看的，
     **缺什么才判得了**：用户/产品对「用户需不需要知道同一份后端有几个落点」的判断。

## §H 一句话（如果只读一行）

**代码只有一份**（`remote-daemon-proto` 的 `[[bin]] cc-monitor-remote`，读数支持 `R24` 裁定一）；
**载体三种、落点四个、闭集表达一个半**；
**三者的 `BUILD_ID` 恒等而那句恒等一格证据都不提供**（同一处抠 + 手 bump）；
**而三个载体里唯一没有身份清单的那个（③），恰恰是解析次序里第一个被采用的。**
