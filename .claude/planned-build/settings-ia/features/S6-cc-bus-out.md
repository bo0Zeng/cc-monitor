# S6 — cc-bus 驾驶舱移出设置，成为顶层运营视图

## §0 前置决定：**顶栏怎么收 → 不加第 7 个图标**

（用户 2026-07-31 把这个决定交给我：「其他你自己决定」。）

顶栏已有 6 个 28px 图标（设置 / 历史 / 全景 / 用量 / 多 agent 监控 / SFTP），
`main.ts` 自陈「顶栏已拥挤」。

**仓里已经为这件事立过先例**：F84 加命令面板（Ctrl+K）时逐字写着
「键位唯一入口（palette 惯例，**顶栏已拥挤，按钮延后**）」——那一次的决定就是
**新入口不再占顶栏**。这次再加一个图标等于推翻它，而我没有新理由：
驾驶舱是**低频**运营视图（不是每次开 app 都要看），恰恰是命令面板服务的对象。

⇒ 入口 = 命令面板一条「打开 cc-bus 驾驶舱」。也符合面板自陈的范围
（「只读命令面板：组装既有 view/dispatcher 目标」—— 开视图是导航，
不是被首刀排除的写/驱动动作）。

**没有考虑过的第三条路**：把 6 个图标收进 overflow 菜单。那要动全部 6 个入口、
影响所有既有用户的肌肉记忆，为了一个低频视图不值当。如果将来顶栏还要加东西，
那时再一并重排更合算。

## §1 做了什么

- 新建 `src/views/cc-bus-view.ts`：**很薄的一层壳**（overlay 外框 + Esc + 返回）。
  驾驶舱本体仍是既有的 `CcBusSection` —— 它过了 B03 两轮审计（零定时器、
  登记≠在线、脏数据如实计数），那些不变量连同守卫原样保留，
  **不因为换了个容器就重写一遍**。
- **懒建**：首次 open 才构造。驾驶舱构造会去拉远端机器清单，
  一个从不用 cc-bus 的用户不该为它付那次往返。有测试钉住「构造时零请求」。
- `panel.ts` 删掉 cc-bus 那一页 —— **S2 当初把它临时单列，正是为了这一刻只删一段注册**。
  兑现了。顶层导航回到计划里的 3 个（应用 / 机器 / 改动足迹）。
