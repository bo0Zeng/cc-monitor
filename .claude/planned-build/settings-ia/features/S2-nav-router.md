# S2 — 设置窗左侧导航 + 路由

主计划 §2.3 的骨架。S3/S4/S5/S6 全部挂在它上面。风险栏：高（动主平台主路径）。

## §0 现状与目标

今天 `panel.ts::buildBody()` 是**一列 4 个 `CollapsibleGroup`**，14 个叶子块，
其中 8 个挤在「集成」里（主计划 §2.1：判据不统一 ⇒ 新东西一律进杂物抽屉）。

目标（§2.3）：左侧导航 ~160px + 右侧内容，顶层 **3 个**：应用 / 机器 / 改动足迹。

## §1 本轮做什么、不做什么

**做**：路由器本体 + 导航 + 把**今天已有的 14 个块按 §2.1 判据归位**到路由里。

**不做**（明确划给后续）：
- 机器列表页 / 状态矩阵 → S3。**本轮 `机器` 路由里放的仍是今天的 `RemoteSection` 原样**。
- 机器详情页四栏 / 吸收 4 处 origin 选择器 → S4。
- 改动足迹页的扩充 → S5。本轮该路由里只放已有的「配置面审计」（T02 那张总账表）。
- cc-bus 驾驶舱移出设置 → S6。
- 折叠/警告策略的全面落地 → S7。本轮只落 §2.3 明写的那两处折叠。
- **不拆 `panel.ts`** —— T07 已审计决定不拆，本轮只改 `buildBody` 的组织方式。
- 不改任何 section 的内部实现，不动它们的构造时机（见 §2.3）。

## §2 方案

### §2.1 归位表（按主计划 §2.1 判据「它改的是谁的状态」逐块判定）

| 今天的块 | 归到 | 判据 |
|---|---|---|
| 行为 / 快捷键 | 应用 | 改 monitor 自己的行为 |
| 字体 / 颜色 | 应用 →「外观」[折叠] | §2.3 逐字写明 |
| Claude 数据目录 / 诊断 / 数据存储 | 应用 →「日志与数据」[折叠] | §2.3 逐字写明 |
| 连接（`RemoteSection`） | 机器 | 它就是机器列表 |
| 账号 / 终端集成 / MCP / cc-bus 钩子 | 机器 | **四个都有自己的 origin 选择器**（主计划 §5-4 逐字列出 `accounts`/`mcp`/`cc-bus`/`cc-bus-hooks` 各维护一份 `this.origin`）⇒ 它们改的是**某台机器**的状态。S4 会把这四份选择器换成「当前在哪台机器页」这个上下文 |
| 配置面审计 | 改动足迹 | 它就是那张「你动过我哪些文件」的总账 |
| cc-bus 驾驶舱 | **临时单列一项** | S6 要把它**移出设置**（主计划 §1-1：它是运营视图不是设置）。塞进上面任何一类都是**误归档**；单列一项 ⇒ S6 删掉它就是删一行注册 |

「集成」这个名字**就此消失**（主计划 §2.2：8 个叶子里真属部署的只有 1 个）。

### §2.2 路由器 API（够本轮用，不预造）

```ts
new SettingsRouter({ landingId })     // element = 导航 + 内容的两栏容器
router.addRoute({ id, title, element })
router.navigate(id)
router.activeId
```

`removeRoute` / 嵌套导航项（§2.3 里机器是可展开的子项）**本轮不做** —— S3 真需要时再加。
L1 那次「为消灭一个 dead_code 告警而造投机 API」的教训还在。

### §2.3 构造时机**保持不变**（这是风险控制的关键）

今天 14 个块在 `buildBody()` 里**全部即时构造**（`CollapsibleGroup` 折叠的只是显示）。
路由器**只管显隐**，不改构造时机：

- 不引入懒加载 ⇒ 不会出现「某页第一次打开才炸」这类新失效模式。
- `open()` 里 `this.remoteSection?.refresh()` / `this.dataSection` 这些字段仍在 build 时赋值，
  行为一字不变。
- 主计划 §5-5 提到的「给 `CollapsibleGroup` 加展开回调」**本轮不碰**（它推翻的是 B03 的一次
  明确拒绝，需要「多个消费者 + 实测预加载代价」才够格，本轮两个条件都不具备）。

落地页 = **机器**（§2.3 逐字写明）。**不记忆上次停在哪一页** —— 计划指定了落地页，
记忆会让「落地页」这个决定失效。

## §5 代码审计结果（Phase D）

**做法如实记**：同 S0/S1，未开并行审计 agent（会话运行约束），主线程自审 + 变异兜底。

### 自审揪出一个**我自己引入的 a11y 回归**

给导航加了 `role="tablist"` 之后，顺手按惯例把非当前项设成 `tabIndex = -1`（roving tabindex）
—— **但没实现方向键**。这两件事必须成对：只做前者的后果是那些页**键盘完全不可达**
（Tab 到不了，又没有别的键能到）。已补 ↑↓←→ / Home / End + 焦点跟随，
并补齐 `role="tabpanel"` / `aria-controls` / `aria-labelledby` 的互相引用。

顺带钉住一条容易写漏的：**不认识的按键不 `preventDefault`**
——吞掉的话 Tab / Esc 在导航上会失灵。

### 三条 info 文案的去向（不能静默丢用户可见的解释文本）

原来挂在分组上的三条 tooltip 随分组消失而失去宿主，`tsc` 报了三个 unused。
**没有一删了之**，逐条判定：

- `REMOTE_INFO_TEXT`（怎么连远端）→ 机器页页头 ⓘ。
- `INTEGRATION_INFO_TEXT` **按语义拆成两半**：「Claude 数据目录」是 monitor 自己的配置
  → 应用页「日志与数据」；「PowerShell 集成」是某台机器上的启动器 → 机器页。
  合着搬会让两页各有一半文案对不上眼前的内容。
- `REMOTE_GROUP_INFO_TEXT` → **删**。它逐字写着「当前尚无独立项…留空占位」
  「在上面的『连接』组」，那个组和那个「上面」都不存在了，留着是一句会误导人的话。

为此给路由页加了页头（标题 + 可选 ⓘ）—— 它同时解决了「导航在左边，视线回不来时页面没有锚」。

### 变异验证 10 条（逐条改坏见红、还原见绿）

① 只显不隐（页面越切越叠）· ② 落地页失效（谁先注册谁当家）· ③ 搬运时漏掉 MCP 块 ·
④ 改动足迹页 id 改错 · ⑤ `open()` 不回落地页 · ⑥ 账号块只剩标题没内容 ·
⑦ 去掉方向键（键盘不可达）· ⑧ 方向键不真的切页 · ⑨ 无关键也被吞掉 · ⑩ 焦点不跟着走。

## §6 工程审计结果（Phase E）

- **`panel-groups.vitest.ts` 是「跟着功能改」不是「删碍事的断言」**：它原本钉的是 F82b 的
  四组结构，那四个组名被本轮按判据重排掉了。新断言**比旧的强** —— 旧的只点名 4 个组 +
  抽查几个子分节；新的是逐页完整清单，少/多/错位三种都红。
- **文档零漂移**：`doc/` 与 `README` 里没有任何地方描述设置面板的分组结构
  （grep 到的「14 组」全是测试分组，与此无关）。
- **给 S3/S4 留下的接口边界是清楚的**：路由器只有「注册 / 切 / 现在在哪」。
  `removeRoute` 与嵌套导航项（§2.3 里机器是可展开的子项）**故意没做** ——
  S3 真要动态增删机器页时再加，那时才知道该长什么样。
- **`CollapsibleGroup` 没被改**：主计划 §5-5 提的「加展开回调」需要「多个消费者 +
  实测预加载代价」才够格推翻 B03 的拒绝，本轮两个条件都不具备，没碰。
- **遗留、明确不在本轮**：footer 的「取消」对绝大多数页是谎言（主计划 §5-3 已登记：
  `cancel()` 只 `applyTheme`，而行为/远端/账号/诊断/MCP 全部改即落盘）。
  分页之后这个矛盾更显眼了（取消按钮悬在所有页之上），但修它属于 S7 的范围。
