# S10 — per-account 用量并进顶层用量视图

## §0 复核推翻了计划里的一条前提

计划写着「**设置账号页那个「查看用量」撤掉**」。全仓 grep：**根本没有这个入口**。
per-account 用量今天只在两处：chip 的菜单（「刷新用量」）与账号设置页的用量单元格。
⇒ 「撤掉第三个入口」这件事不存在，S10 的实活只剩「并进顶层视图」这一半。

## §1 顺手修掉一句**已经在说假话**的提示

`OK_USAGE_UNVERIFIED_CAVEAT` 原文：「格式基于训练知识猜测，**尚未经真机验证** ——
百分比的含义（已用/剩余）与具体数值可能不准确」。

那句话在 F10 时是诚实的，**但 E42 之后不再成立**：用户给了真机 `/usage` 抓屏，
解析器据此重写成结构性识别并对照夹具钉住。继续挂着等于告诉用户「这数字可能整体反了」
—— 会让人白白不敢用。

**但也没改成「已验证，放心用」**：残余风险是真的，只是换了位置 —— 探针用
「画面静止 3s」判定渲染完成，那是**预算不是实测值**（本仓不允许起真实已认证的 claude
去测真实渲染耗时）。新文案把这两件事都说清：格式已验证；卡顿超 3s 会抓早，
**但那种情况显示成「认不出格式」并附原始屏，不是给一个错的数字**。

常量名沿用（三处 import 着），只改文案 —— 改名是纯改动面。

## §2 并进顶层视图

用量页此前只讲「已花费 token」，而「还剩多少」是另一半，用户只能在 chip 菜单里看到。
**同一个问题不该有两个地方回答。** chip 上那份**保留** —— 它是常驻状态，不是入口。

两条设计约束，都有测试：

- **按需读取，打开页面不自动探**。一次探测要在远端起 tmux 会话、跑 `/usage`、抓屏。
  打开用量页就自动付这个代价不对，也撞 §1-2。
- **失败必须可见**（主计划点名要求本轮保住的 F10 路径）：认不出格式时说「认不出」+
  **把原始屏带回来** + 「复制诊断文本」；失败时**不显示任何百分比**。
  探测失败 / 未登录 / 没有 claude 各自说清是哪种，不混成一句。

新增的 `writeText` 已登记进 `paste-block-guard` 的**族 B**（复制完就完事，
不是待贴配置文本）—— 那条白名单守卫正是为「新增即红、必须过一次审」而立的。

逐条改坏见红、还原见绿。
