# S8 — 「基座」一词从 UI 消失

## §0 先找齐再改

全仓 `基座` 命中约 40 处，**绝大多数是注释**。用户可见的**恰好五处**（与计划对上）：

| # | 位置 | 原文 |
|---|---|---|
| 1 | `launch-menu.ts:74` | `label: "基座（不隔离）"` |
| 2 | `machine-card.ts:851` | 「不指定（用远端登录的**基座**账号，不注入 CLAUDE_CONFIG_DIR）」 |
| 3 | `tabs.ts:2326` | 重启项 title：「不提供「**基座**」选项：…」 |
| 4 | `cc-bus-section.ts:228` | 「账号：**基座**（不注入任何账号）」 |
| 5 | `cc-bus-section.ts:468` | 「**基座**（无账号）」 |

**内部标识符不改**（`kind: "base"` / `useBase` / `__base__`）—— 那是实现词汇，
改它们只制造改动面、不改善任何人看到的东西。

## §1 换成「不指定账号」

「基座」是内部叫法，指「不做账号隔离、直接用继承来的 `CLAUDE_CONFIG_DIR`」。
对用户它什么都没说明 —— 既不是账号名，也不提示会用哪个身份。

候选里选「**不指定账号**」而不是「默认账号」或「不隔离」：
- 「默认账号」**会撒谎** —— 系统里可能真有一个「默认账号」，而这一项恰恰是**不注入任何**账号。
- 「不隔离」说的是机制，不是用户在做的选择。
- 「不指定账号」说的正是那个动作，且**有现成依据**：`machine-card.ts` 那条本来就写着
  「不指定（…）」。跟着既有措辞走比再发明一个词好。

## §2 守卫：写了个二十行的小词法器，不是拿正则凑

**两种偷懒扫法各自被对方的问题绊住，都实测产生了假红**：

1. 「剥掉注释再 grep 全文」—— 剥不干净**行尾**注释（`const x = 1; // 落基座`）。
   实测：`launch-plan.ts` / `launcher-diagnostics.ts` 假红。
2. 「直接正则抠字面量」—— 被**注释里的引号和反引号**骗。注释里写着
   「恒含"基座（不隔离）"逃生口」，正则照样抓出来。实测：6 个文件假红，
   其中还有两条根本不含「基座」（跨行配对错了）。

⇒ 一个记录 in-string / in-comment 状态的**单趟扫描**两者都对。守卫本身也有测试
（认块注释、认转义引号、注释里的不算、字面量里的要抓到）。
