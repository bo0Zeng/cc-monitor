## §2 目标信息架构

### §2.1 分组判据（一句话，可机械执行）

> **每个顶层 = 一类「被设置的对象」。进去 = 选定这类里的一个实例。**
> 新功能来了只问：**它改的是谁的状态。**

第二条（决定折叠）：**「读一次就够的」可进 ⓘ；「不读就会做错事的」绝不能藏。**

**现在为什么乱**：4 个组名**不在同一抽象层**——「连接」是动作、「外观」是切面、「账号」是切面、「集成」是其它。判据不统一 ⇒ 新东西一律进「集成」（8/14 叶子）。

### §2.2 为什么**不**做「部署 → 远端/本地」分栏

用户的诉求对（部署该归堆、不该与别的同级），但**作用域在上、部署在下**，两条硬理由：

1. **`parity_ledger` 把这条轴算死了**：121 命令 → 50 能力 → 20 不对称里，**永久只有一侧的仅 7 项，其中 6 项远端独有**；本地独有只剩 `search.index`，而理由表自陈它「**是本机侧的实现细节，不是一项对外能力**」。§0.1-4 把 panorama 改判 `ParityDebt` 后，本地独有**进一步清空**。⇒ 「本地」栏按项目自己的账本终将为空，**把待还的欠账做成 UI 主轴 = 把欠账固化进信息架构**。
2. **多机即崩**：三台远端要三栏吗？正确形态是「机器是列表、本机是其中一行、每台下同一组组件」。

**「集成」这个名字直接消失**，不是改叫「部署」——8 个叶子里真属部署的只有 1 个。

### §2.3 结构

```
设置窗（左侧导航 ~160px + 右侧内容 ~580px）

应用
  行为 / 快捷键 / 外观[折叠] / 日志与数据[折叠]

机器                          ← 落地页
  工具条：+ 添加 · 从 ssh config 导入 · 批量导入 · 端口转发 · [x] 启用远端模式
  ├ 本机                      ← 第一行、不可删（§40 的诚实表达）
  ├ aya    ✓3分钟前 daemon✓ ccm✓ acct-iso✗ 2账号
  └ nano   ✗连不上   —      —     —        ⚠3字段不全
      点行 → 详情页：[连接] [组件] [账号] [工具]

改动足迹
  按机器分组：碰过哪些文件 / 做了什么 / 现状 / 能不能撤
```

**顶层 3 个**（比现在少），但导航可见项 = 4 + 1 + N台 + 1。
**「四个太少」是误诊**：真实分布是 1/4/1/8 —— 不是数量少，是**一个杂物抽屉撑爆**。按「太少」去加会长出第二个 `remote-placeholder`（「账号」组今天的 id 就是当年空占位组的遗骸）。

### §2.4 机器详情页「组件」栏 —— 三处部署首次同屏

| 组件 | 远端 | 本机 |
|---|---|---|
| 数据源 daemon | 装/卸/版本 | **不需要**（`watcher.rs` 直读 jsonl，§40 天然不对称白名单） |
| 启动器 | ccm 装/卸 + **这台机的启动命令** | PowerShell 集成（未来 POSIX ccm） |
| 多账号 | cc-acct-iso 装/卸 | L3a 后端已就绪、**缺入口** |
| cc-bus 钩子 | 诊断 + 待贴片段 | 诊断 + 待贴片段 |

「这台机的启动命令」是**新增的 per-machine 化**：今天 `resumeCommandRemote` 是**全局单值**，但语义应是 per-machine（A 机装了 ccm、B 机没装，今天无法分别表达）。见 §5 建模问题 1。

## §4 已知风险（每条都有出处）

1. **懒构造让 `safeBlock` 失效而测试全绿**。`safeBlock` 在 `buildBody()` 构造链上；页面懒构造发生在 click handler 里 ⇒ 隔离失效，而 `panel-block-isolation.vitest.ts` 5 条只测构造期、**保持全绿**。⇒ **页面构造必须自带 `safeBlock`**，且新测试要能被「把 `build()` 求值移出 try」这个变异打红。
2. **`info-icon.ts:47` 无销毁路径**（16 个调用点）。窗口销毁模型下无害；**页面级构造/销毁会稳定泄漏**。⇒ 加 `destroy()` 必须**先于**页面化。
3. **`panel.ts:181-210` 那 8 个 `!` 字段**由 `safeBlock` 内部赋值、被 `openInner()` 解引用。分页 + 懒构造后必然 undefined ⇒ 现被外层 try 兜成「整个面板不 hydrate」。**必须把 sync 挪到各页 `onEnter`**。
4. **6 条文件级源码扫描**（`cc-bus-section` 无定时器 / `cc-bus-hooks` 绝无写入 / `config-surface` 不得写 / `accounts-section` 零写盘 …）：**搬走被守的代码后断言仍全绿，但守的范围缩小了**。⇒ 拆文件必须同步扩到**目录级**。
5. **给 `CollapsibleGroup` 加展开回调 = 推翻 B03 的一次明确拒绝**（`cc-bus-section.ts:13-16`：「为一个消费者去改共享 UI 原语，正是 R12/R15 反复拒绝的」）。**推翻条件**：多页化提供了**多个**消费者 + 实测预加载代价。要在功能计划里写明「B03 当时拒绝的是单消费者场景，条件变了」。
6. **`vi.mock` 路径硬编码**：移动/改名任一 section 文件，对应 mock 静默失配、真实模块被加载 ⇒ 难查的超时而非清晰的红。**拆文件前先做一次一次性实验验证**。
7. **`jump` 是跨机器引用**（另一台的 label，无校验）。「每台机器独立」这个 IA 承诺在此处是假的 —— 删 A 会让 B 的 jump 悬空。
8. **只有 1 台机器时导航多一层**。用户已答「按多台来搞」⇒ 接受；但 1 台时应直接进详情页，不看只有一行的列表。

## §5 顺带查出的三个建模问题（不是本计划引入，但会被顶到台面）

1. **`resumeCommandRemote` 是全局单值，语义应是 per-machine**。而「装 ccm」是 per-machine 按钮 ⇒ 装完 ccm 却忘改 resume 命令是**结构性陷阱**（今天那两处隔着两个顶层组）。S4 把它 per-machine 化。
2. **`defaultName`（当前账号）是全局单值，账号是 per-origin**。chip 绑「第一台非 daemonless 远端」⇒ **两台远端各有账号时那个选择器在说谎**。本计划**不改数据模型**，但 chip 至少要显示它绑的是哪台。
3. **footer 的「取消」对面板 90% 内容是谎言**：`cancel()` 只 `applyTheme(this.original)`；行为 toggle / 远端配置 / 账号 / 诊断 / MCP / PowerShell **全部改即落盘**。⇒ 外观页保留**局部**「取消 / 恢复外观默认」，其余页面明确「即时生效」。
