## 摸底：先重测那一格（血泪 8）

计划把 `launch.rs:304` 列成「那个真 bug」。**重测结论：它不是 bug，但它旁边有一句真的在撒谎。**

### 逐条实测

| 断言 | 实测 | 判定 |
|---|---|---|
| `launch_remote_terminal` 无条件调 `launch_powershell_window` | ✅ 属实（`launch.rs:304`，函数体里只有 `#[cfg(windows)]` 的 ssh 预检，**拉起那一步无 cfg 分支**） | 属实 |
| 非 Windows 上它直接 `Err` | ✅ 属实（`launch.rs:269-271`） | 属实 |
| 「不是缺口，有刻意的剪贴板兜底」 | ✅ 属实。`remote-launch-run.ts::invokeLaunchOrCopyFallback` catch 住 ⇒ 写剪贴板 + toast 带上命令原文 | 属实 |
| ⇒ 所以「功能永不变砖」 | ✅ 属实，但**代价是它把一条刻意的设计报成了失败** | **← 真问题在这里** |

### 用户在 Linux 上实际看到什么（逐字）

- 标题：**「拉起失败，已复制 resume 命令」**
- 正文：**「拉起终端窗口仅支持 Windows（v1）」** + `到远端 [x] 的 ssh 终端粘贴执行：` + 命令原文

**两处在撒谎：**

1. **「拉起失败」** —— 在 POSIX 上这不是失败，是**既定设计**。把设计行为报成失败，
   会训练用户把一个正常状态当成坏了。
2. **「仅支持 Windows（v1）」** —— 那个 `(v1)` 暗示「v2 就支持了」。
   而 **L1 早就裁决过反面**，逐字写在 `launch.rs::launch_local_posix` 的头注里：

   > **不开 GUI 终端窗口**。POSIX 上没有「唯一的终端」这种东西，而会话容器本来就是 tmux
   > （`ccm --tmux` 自己会建）。开窗口要先猜用户用哪个终端模拟器，**是平白引入一个
   > 会在别人机器上错的决定**。⇒ 命令直接跑，会话留在 tmux 里等 attach。

   ⇒ 「以后会支持开窗」这件事**不但没排期，而且方向是反的**。

### 真正缺的那一半（本轮**做不了**，与 U8a-2c 是同一个阻塞）

实测出一处真的不对称：

| | 本机 resume | 远端 resume |
|---|---|---|
| OS 分派 | **有** —— `history.rs::launch_local` 里 `#[cfg(windows)]` 走 PowerShell 窗口 / `#[cfg(not(windows))]` 走 `launch_local_posix`（不开窗、detached、会话留 tmux） | **没有** —— `launch.rs:304` 一律 PowerShell |
| Linux 上的结果 | **真的把会话起起来了** | 只复制命令，**会话没建** |

按 L1 的同一形态补齐（POSIX 宿主上 `ssh …` detached 跑一遍，会话留在远端 tmux 里等 attach）
在**语义上成立**：渲染出来的命令是 `new-session -d … && send-keys …; tmux attach …`，
没有 TTY 时前两步照常成功、`attach` 无害失败 —— 正是「命令直接跑，会话留 tmux」。

**但本轮不做，理由是结构性的**：

- 那条 tauri 命令收到的是**一条渲染好的 shell 串**，拆不回「只建不接」的变体。
- 于是只剩两条路，都不能接受：
  ① **fire-and-forget** —— 因为 `attach` 必然失败，退出码永远非零，**分不出「auth 失败」
     与「只是没 TTY」**。stdio 全 null 之后用户什么都看不到 ⇒ **静默失败**，比今天更糟；
  ② **切字符串**（把尾巴上的 `; tmux attach …` 剪掉）—— 解析渲染产物，脆得没法维护。
- 干净的解法是让前端发**结构化请求**（U8c 的两个 TS 渲染器 + IR 退役）之后，
  在 POSIX 上走 daemon 的 `launch`（U8a-2b 已经建好，**它天生就是「只建不接」**）。

⇒ **并进 U8a-2c**（生产切换）一起做，依赖 U8c。本件把这条阻塞写清楚，不硬做。

## DoD

1. **判定落档**：`launch.rs:304` 不是 bug；真正的不对称是「本地有 OS 分派、远端没有」，
   且它与 U8a-2c 同一个阻塞。
2. **把那两句撒谎的文案改成实话**：后端错误文案 + 前端 POSIX 上的标题。
2b. **分档判据按「后端自己的声明」，不按 `hostOs`** —— `hostOs !== "windows"` 会把
   **真失败**（配置缺失 / 命令被拒 / spawn 崩）也一起软化成「这是设计」，那是另一种撒谎。
3. **一条护栏**把 L1 那条决定钉住：`launch.rs` 生产段**不许出现任何终端模拟器**
   （防以后有人顺手加个 `gnome-terminal` 探测）。零命中型。
4. **文档提升**：这条决定今天只活在一句代码注释里 ⇒ 写进 `doc/ARCHITECTURE.md` 与双语 README。
5. 平面 ③ 的边界写死：**daemon 在远端，开不了你面前的窗 —— 这一条永远搬不走。**

### 不做什么

- **不做终端模拟器探测/分派**（L1 已裁决，方向相反；真要做是产品决定，不是清理）。
- **不补远端 POSIX 拉起**（见上，结构性阻塞 ⇒ U8a-2c）。
- **不动 Windows 那条路**一个字节。
