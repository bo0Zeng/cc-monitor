# U10 摸底裁决 —— ⚠ 本件的两条结论 2026-08-03 当天被订正，见开头

> ## ⚠ 订正（同日，用户点出「我记得我之前就定过这些原则」后核主计划）
>
> **本件有两条结论是错的**：
>
> 1. **「接」不属于 U10 —— 错。** §1.3 的原话是「区别不在那个进程存不存在，在**它有没有
>    决策权**」，§1.4 是「窗口里跑什么由 backend 给」⇒ **接的决策归 `control/`，只有 `exec`
>    留在终端**。我把「执行不能搬」错当成「整件不属于后端」。**「接」重新纳入 U10。**
> 2. **「Gate 2 没搬所以切不动」—— 那不是阻塞，那是活。** §1.1 逐字写着「**任何改状态的
>    tmux 命令（`set-hook`/`set-option`/`new-session`/`kill`/`send-keys`）一律归 `control/`**」。
>    搬 Gate 2 本来就是 U10 的内容，我却把「还没搬」写成了「需要裁定」。
>
> **失误的形状**：把「今天还没做」写成「还没定」。铁律 4 是「计划前提被实测证伪就改计划」，
> 而这里计划前提好好的，只是没做完。**下面的实测数据全部有效**（Gate 2 在哪、daemon 缺什么、
> 四件各自的形态），**只有「因此切不动」那层结论作废**。
> `tmux_daemon_gate_guard` 保留 —— 它钉的「Gate 2 没搬进 daemon 之前别改走 daemon」仍然对，
> 而且它的前提触发器正好会在 Gate 2 搬完那天提醒撤禁令。

# 原文（实测部分有效，结论层见上方订正）

- 工作区：unified-backend · 任务 #98
- 本件性质：**摸底 + 裁决 + 把裁决钉成机检**。零功能变化。

## 一、逐件量过的结论

| 件 | 判定 | 硬理由（实测） |
|---|---|---|
| **接（attach）** | **从 U10 剔除** | §1.3 把最终 exec/attach 钉在**用户自己的终端进程**里（pid 要等于 pidfile 名、tty/Ctrl-C 要落在 agent 上、`tmux attach` 要占住调用方终端）。daemon 在远端，**开不了你面前的窗**。它不是「还没搬」，是**结构上不该搬** —— U8a-2c 已经把这条边界用在生产里了（`send-into` 的 attach 半边留在终端） |
| **send-keys** | 切不动（两条） | ① daemon 的 `launch{send-into}` **恒附 Enter**，而 `Escape`（`enter:false`，优雅退出用）表达不了；② **更硬的一条见 §二** |
| **停（kill）** | 切不动（更重） | §34 的**三道门 + 原子 verify+act**（一次远端往返内完成，防 TOCTOU）。daemon 侧要复现三道门才可能切，比 send-keys 还多一层 |
| **用量探针** | 切不动（上一轮已判） | 它走 `connect_and_exec_cmd`（**一次性 SSH exec**），而 daemon 客户端只活在长连接上 ⇒ 只搬「建会话+键入」那半会变成**两个通道**、更慢更脆，`capture-pane` 还得回到一次性 exec |

⇒ **U10 名下今天一件也切不动，而且四件的理由互不相同**。这不是「难」，是四条不同的结构约束。
按 U8a-2c 的做法：**把裁决落档 + 把最危险的那条钉成机检**，而不是硬切。

## 二、那道会被悄悄丢掉的门（本轮最要紧的发现）

monitor 的 `tmux_send_keys` / `kill_remote_tmux` 带着 §34 的 **Gate 2 union**：
目标要么本地 `is_ccm_tmux_name` 命中（`cc-*` 前缀），要么**远端 `@ccm_sid` 已设** ——
后者由**嵌进远端命令的守卫**核验，不通过回 `CCM_GUARD_REJECTED`。
那道门挡的是「往一个**不是本工具管理**的 tmux 会话里打字 / 把它杀掉」。

而 daemon 的 `control/launch.rs` 实测：**只核会话存在性**（`no_such_session`）。
它**写** `@ccm_sid`（建会话时 `set-option`），但**从不核验**它。

⇒ 把 `send-keys`/`kill` 改走 daemon，**等于丢掉 §34 的 Gate 2**：
功能看起来一样、门禁全绿，而一道门没了。**这正是本工作区一路在治的那个形状。**

★ 顺带解释了 U8a-2c 为什么敢切 `send-into`：**那条路本来就没有 Gate 2**
（`session-backend.ts` 产的裸 `send-keys` 不带身份守卫，它的安全性来自「会话名是自己刚挑的」）。
两件事的差别不是勇气，是**那条路上有没有门**。

## 三、一条陈旧注释（P2 家族）

`tmux_send_keys` 的头注写着「走一次性 ssh、**daemon 不参与**（**守只读边界**）」——
那个前提**自 U3/U8a-2b 起已经不成立**（daemon 有 `control/` 写面了，U8a-2c 还接了第一条生产调用）。
理由过期而结论仍对，是最难发现的一种陈旧：**读的人会以为「daemon 只读」还是红线**。
已改成真实理由（Gate 2 未搬），并指向下面那条机检。

## 四、`tmux_daemon_gate_guard`：**前提触发器**，不是永久禁令

| 判据 | 变异 | 结果 |
|---|---|---|
| daemon 侧没有 Gate 2 之前，那两个命令不许出现 daemon 通道（`inbound_client` / `daemon_send_into`） | 往 `tmux_send_keys` 里塞一行 `client_for` | **红** |
| **前提触发器**：daemon 侧一出现身份守卫标志（`CCM_GUARD_REJECTED` / `wrong_owner` / `not_owned`）⇒ 主动红，逼人回来重新裁定 | 往 daemon `launch.rs` 加一个 `wrong_owner` 常量 | **红**（文案写着「**这是好事**，但禁令的前提变了，请回 U10 重新裁定」） |
| 抽取器自检（函数体抽得到、且里面还有 `connect_and_exec_cmd`） | 把截取长度改成 10 字节 | **红** |

这个形状与 `env_reset_can_never_be_reached_in_the_cli_renderer` 同源：**钉的是前提本身**，
前提一变就叫人回来 —— 而不是写一条「以后记得」的注释。

## 五、S29 那条 data-poll（`awaitExitFor`）为什么本轮也没退役

它归 U10，本轮量了：Rust 侧**确实**已有帧推来的全局 tmux 账本
（`ssh_source.rs:1039`：`origin → 最新 tmux ls 原文`，写者 = `stream_loop` 收 `TmuxSessions` 帧）。
但同一个文件的注释写着那份账本**最长 8s 陈旧**、且是 **command-agnostic** 的。

⇒ 改成等帧 = 把「1s 一次 SSH 往返」换成「**最长 8s 才知道**」，而
`awaitExitFor` 卡在一条 UX 路径上（换号重启要等它退出才继续）。
**这是延迟与网络负载的取舍，需要产品判断，不该由我替用户定。**
⇒ 如实登记：S29 里那条仍归 U10，解锁条件是「先定 8s 陈旧可不可接受，或让 daemon 发一条
即时的『claude 退了』帧（今天 `EMITS` 里的 `tmux_session_closed` 是**会话关闭**，
不是**会话里的 claude 退出**）」。
