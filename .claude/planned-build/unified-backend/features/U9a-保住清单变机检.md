### ★ 摸底顺带查出一个真的：`--print` 在撒谎

`--print` 的定位是**平价预言机**（`e2e/ccm-print-parity.sh` 头注：「唯一能在没有真远端机器的场景下

实测两条路（非容器路径）：

```
$ ccm --agent codex --print          （TMUX 已设、tmux shim 回 faux-sess）
cd '/…' && exec codex

$ ccm --agent codex --launcher env   （同一环境，真跑）
CC_BUS_ID=faux-sess                  ← --print 没说这一句
```

`--print` 那段与真 exec 那段（`do_print` 分支 vs 其后的「非容器路径」段）是**两份手写副本**，

## 设计

### A 组为什么用「进程环境」而不是「字符串比对」

比对两段 shell 文本只能证明「文本像」，而 `--print` 与 exec 路本来就写法不同
（`export X=$(sq …)` vs `export X="$x"`）。**差分的对象必须是效果**：
- `--print` 那条串 → `bash -c "<串>"`，把 `exec` 的目标换成 `env`，拿到「预言的环境」；
- 真跑 `--launcher env` → 拿到「实际的环境」；
- 两边都只取 **ccm 受控的那几个键**（`CLAUDE_CONFIG_DIR` / `ANTHROPIC_MODEL` / `CC_BUS_ID`
  / 嵌套标记），其余（PATH 等）不比——比全集会被宿主环境噪声淹没。

这样「`--print` 少说一句 export」**必然**红，而写法差异不会假红。

### C 组的诚实边界

`capabilities=` 那条查的是**覆盖**（`⊇`）不是相等：ccm 多声明能力是允许的
（今天就多 6 项），少声明才是病。这一点要写进断言名，免得以后有人把它「收紧」成相等
然后每加一个 flag 都红。
