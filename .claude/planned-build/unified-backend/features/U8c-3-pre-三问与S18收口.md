## 一、§33b 三问逐条回答（实测）

`doc/INVARIANTS.md` §33b 写死了「删/搬 `session-backend.ts` 前必须先回答三件事」。逐条：

| # | 问题 | 实测答案 |
|---|---|---|
| 1 | 生产是否已切到 daemon 的 `launch`？ | **否。** 全仓 `.call("launch", …)` 只有 `inbound_client.rs:943` 一处、在 `#[cfg(test)]` 里；`ssh_source.rs` 还专门断言 `!client.accepts("launch")`。⇒ **U8a-2c 仍未做** |
| 2 | attach 那条串归谁产？ | **一半有答案、一半没有。** 装了 ccm 的主机：**已经是 Rust 产的**（U8c-2c-2 起走 `render_ccm_invocation` 的 attach 早返回分支，产 `ccm attach <名>`）。**没装 ccm 的主机仍靠 `session-backend.ts::attach`** —— 删了它那条路就断 |
| 3 | daemonless 的远端还要不要能起会话？ | **未决。** `MASTERPLAN:324` 的 **U12「daemonless 处置」仍是待做项** |

⇒ **U8c-3 今天做不了**：第 1 问是「否」、第 3 问「未决」。硬删 `session-backend.ts` 会把
「没装 ccm 的远端 / daemonless 的远端」两类主机的起会话能力直接删掉，而那两类今天都还成立。

**这不是拖延，是 §33b 那三问的设计目的** —— 它就是为了让人在删之前撞上这三件事。

## 二、改做：账本 S18 的两处收口（U8c-1 自己开的那条缝）

S18 记着 U7-3 把 `is_deceptive_char` 收进 `acct-core` 时**漏了拼命令那条路**。
U8c-1 补了 Rust 命令面，**并在 §33b 里如实登记「这次变严在两种语言之间开了一条新缝」**：
同一个含 `U+3000` 的 configDir —— **本机 Rust 拉起拒绝、远端 TS 拉起放行**。

本件收掉剩下两处：

| 处 | 收法 |
|---|---|
| **TS `shell-quote.ts::isValidConfigDir`** | 正则补齐那六段（TS 没法 import Rust crate ⇒ 只能手抄）+ **一条读 Rust 源码的行为对拍** |
| **Windows `history.rs::SPOOFABLE`** | 改调 `acct_core::is_deceptive_char`，**旧表整个删掉**（留着不用 = 旧集合还在仓里等下一个人复制）|

⚠ **为什么 Windows 那处可以合、而 `is_safe_config_dir` 不行**：`acct-core` 头注裁决「不合」
的是**路径规则**（`\` 与盘符 —— 真平台特化）。「什么算视觉欺骗字符」是**平台无关**的判断，
不在那条裁决的范围里。

## 三、判据（本轮每条都先问「它能不能红」）

`shell-quote-deceptive-parity.vitest.ts` —— **行为对拍不是文本对拍**：
从 `acct-core/src/lib.rs` 的 `matches!` 里解析出全部码位（含 `..=` 区间展开），
把**每一个**真的塞进一条合法路径喂给 `isValidConfigDir`。

| 变异 | 结果 |
|---|---|
| TS 退回旧表（正是本轮要收的缝） | **红**，逐个报出 `U+1680` 等 18 个漏网码位 |
| Rust 并集加一个新码位而 TS 没跟 | **红**（报 `U+180E`） |
| TS 变成「什么都拒」 | **红** —— 反向自检挡住「全拒冒充成功」 |
| 抽取器解析不出码位 | 自检 `>= 30` + 四个定点核 |

⚠ **前三轮我写的判据初版都不合格**（恒真自检 → 只覆盖三分之一 → 匹配到散文里的关键词），
形状是同一个：**匹配面比声称的宽**。本轮的对拍刻意做成**行为级**（真喂码位、看拒不拒），
而不是比正则文本 —— 文本比对正是那三次栽的地方。
