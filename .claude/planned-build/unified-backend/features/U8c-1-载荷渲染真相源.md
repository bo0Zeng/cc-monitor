计划把 U8c 说成「两个 TS 渲染器」。实测**同一段「账号 env 前缀 + 嵌套 env 清理 + launcher」
今天有四个产出点**，跨两种语言：

### ★ 外层 tmux 那半本件不搬 —— **但不是因为它「已经没了」**（我第一版这么写，被审计证伪）

我原本写「外层在 U8a-2b 就已经被 `control/launch.rs` 用 argv 直传取代」。**三条都不成立**（实测）：

1. **daemon 的 `launch` 零生产调用方** —— 全仓 `.call("launch", …)` 只有一处且在 `#[cfg(test)]` 里，
   `ssh_source.rs` 还专门断言 `!client.accepts("launch")`。**STATUS 自己就写着「生产路径尚未切换 ⇒ U8a-2c」**，
   我那句与它自相矛盾。
2. **`control/launch.rs` 结构上不覆盖 attach** —— 模块头注逐字「本模块**不 attach**」（平面 ③），
   而 `session-backend.ts` 产出的串尾巴就是 `tmux attach -t …`。
3. **Rust 侧今天就在拼外层** —— `account_usage.rs::build_usage_probe_cmd` 是生产代码，
   一整条 `tmux kill-session … new-session … send-keys … capture-pane`。

⇒ **决定不变**（本件只搬内层载荷，`session-backend.ts` 不进范围），**但理由换成正确的那个**：
「先做被依赖的」。外层的四个产出方一个都没退役，处置写进 `doc/INVARIANTS.md` §33b。

## DoD

1. **新 crate `src-tauri/crates/launch-core`**，形态照既有四个共享 crate（零依赖、平台中立、
   `daemon` 侧以 `path = "../src-tauri/crates/…"` 依赖）：
   - 载荷 IR 的 Rust 表示（`EnvOp` / `Action` / `Wrap` 的最小必要子集）；
   - `render_payload()`：`env ops → cd → argv → wrap` 的编译，**与 TS 逐字节相同**；
   - `posix_quote()` 与**命令面** configDir 校验，其不可见字符判据**建立在
     `acct_core::is_deceptive_char` 之上**（不是再抄一张表）。
     ⚠ **不合 `is_safe_config_dir`** —— acct-core 头注已裁决那是刻意的平台特化。
2. **跨语言逐字节对拍，且不是自洽夹具**（血泪：U7-4 的病根就是「写侧读侧同一个常量」）：
   - TS 侧生成一份**入库的** fixture（`N` 组 `{plan, payload}`）；
   - Rust 测试读**同一个文件**、自己渲染、断言逐字节相等 + **条数自检**；
   - TS 侧一条测试断言「入库的 fixture == 现场渲染」⇒ 改 TS 不重生成 ⇒ 红。
   ⇒ 改任一侧都会红，且**红在正确的那一侧**。
3. **至少一个真生产消费方**（否则是「加了个 crate 没人用」）：`history.rs` 的 **POSIX** 分支
   改用 `launch-core` 的前缀渲染与校验。**Windows 分支一个字节不动**（`$env:` 是平台变体，
   且真机验证归 U4b）。
4. **行为变化只有一处，而且是变严**：`history.rs` POSIX 校验的不可见字符集合从
   U7-3 之前的旧表换成 `acct-core` 的并集 ⇒ 多拒 6 段码位。**渲染产物对合法输入逐字节不变**
   （有测试）；多拒的那几段各有一条测试点名。**不许写成「零行为变化」。**
5. 六条 INVARIANTS 逐条判定「本件动没动 / 后两件会怎么动」，写进文档。

### 不做什么

- **不切生产渲染路径**（`remote-launch-run.ts` 仍走两个 TS 渲染器）—— 那是 U8c-2。
- **不删任何 TS 文件**、不动 `launch-plan.ts` 的类型 —— 那是 U8c-3。
- **不搬 `session-backend.ts`**（外层 tmux 已被 `control/launch` 的 argv 取代，见摸底）。
- **不动 Windows 分支**、不动 `renderCli`（ccm 调用形态是另一种语法，U8c-2 再说）。
- **不给 daemon 加新命令** —— 本件只建内核，接线归 U8c-2。

## 设计

### 为什么是共享 crate，不是 daemon 独有

三个消费方，两种宿主：
- daemon（远端执行面，U8c-2 之后要用它产载荷）；
- monitor 的 Rust 侧（**本机** POSIX/Windows 拉起，今天就在自己拼）；
- daemonless 的远端（U12 未决 —— 若判定要支持，monitor 侧也得能渲染）。

⇒ 与 `branch-core`/`usage-core`/`acct-core`/`guard-core` 同一个理由、同一个形态。

### ★ 校验器：账本对这件事**已经有过裁决**，我先查了（铁律 3）

`acct-core` 的头注逐字写着 U7-3 的三分裁决：

> | `is_deceptive_char` | **平台无关**，而且两侧**双向漂了** ⇒ 合，取并集 |
> | `is_safe_config_dir` | monitor 用 `looks_absolute`（认 Windows 盘符）… **是刻意的平台特化，不是漂移** ⇒ 不合 |
> | `norm_dir` | 同上 ⇒ 不合 |

⇒ **我第一版计划里那句「configDir 校验取并集」与这条裁决冲突，已删。** 本件不合
`is_safe_config_dir`。

### 但同一次查证翻出一处 U7-3 **漏掉的**同族副本

U7-3 把 `is_deceptive_char` 收进 `acct-core` 并让两个**读 manifest** 的地方共用
（`local_accounts.rs:110` · `accounts_query.rs:89`）。**拼命令那条路没跟上**：

| 位置 | 用的是什么 | 集合 |
|---|---|---|
| `local_accounts.rs` / `accounts_query.rs`（读 manifest） | `acct_core::is_deceptive_char` | **并集**（含 `U+1680` · `U+2000..200A` · `U+202F` · `U+205F` · `U+2060..2064` · `U+3000`） |
| **`history.rs::SPOOFABLE`（拼命令）** | 自己那张 18 项表 | **U7-3 之前的旧集合** —— 上面那些一个都没有 |
| TS `shell-quote.ts::isValidConfigDir`（拼命令） | 自己那条正则 | 同样是旧集合 |

`history.rs` **全文零 `acct_core` import**（实测 `grep -n acct_core src-tauri/src/history.rs` 空）。
所以 `/home/u/.claude-accts/<U+3000>z` 这种目录：读 manifest 时会被拒，**拼进
`export CLAUDE_CONFIG_DIR='…'` 时不会**。

⚠ **诚实定级：这是纵深防御的缺口，不是今天可利用的洞。** 两条理由（第二条更硬，工程审计补的）：
① configDir 的上游 —— **manifest 读取**与 **`/proc/<pid>/environ` 探针**（E79 加的，**不是 manifest**，
我第一版的枚举漏了它）—— 都经 `local_accounts::is_safe_config_dir`，那个函数用的就是并集；
② **就算漏过去也不可能是注入**：新旧两张表都拒掉了包括 `'` 在内的全部 shell 元字符，而值是**单引号包裹**的；
多拒的那几段全是不可见空白类，最坏后果是**视觉冒充 / 静默串号**（`…/<U+3000>z` 在 UI 上看着就是 `…/z`）。
第二条不依赖别处的实现不变，比第一条稳固。
⚠ **精度订正**：`config_dir.trim()` 会把那六段里的五段在**首尾**位置吞掉（它们 `is_whitespace()` 为真），
只有 `U+2060..2064`（Cf，非空白）在首尾也会被拒。所以「多拒六段」只在**路径中间**成立 —— 测试正是这么写的。
但「daemon 是权威也保留本地校验」正是这个仓自己写在 `resolve_query.rs` 头注里的纪律
（B2：对自己产出的东西也过一遍）—— 少一层就是少一层。

⇒ **本件的处置**：`launch-core` 的命令面校验建立在 `acct_core::is_deceptive_char` 之上，
`history.rs` POSIX 分支改调它 ⇒ 那张旧表退役。**这是行为变化（变严），不是零行为变化** ——
下面 DoD 第 4 条据此改写。

### 诚实边界

- **本件之后仍有四个产出点**，只是其中一个（`history.rs` POSIX）改成了调内核。
  U8c-2 收编 TS 那两个，U8c-3 删掉它们。**别把本件读成「合完了」。**
- **Windows 分支（`config_dir_prefix_ps` / `validate_config_dir_ps`）一个字节不动**，
  于是**那张旧表在 Windows 那条路上还活着**。合并它要先回答 acct-core 已经裁决过的
  「`\` 与盘符」问题 ⇒ 留给 U4b（真机）或 U8c-3，**登记在案，不假装做完了**。
- `render_payload` 的 Rust 实现**今天没有生产调用方产出完整载荷** —— 它只被
  `history.rs` 用到了「前缀」那一段。完整载荷路径要等 U8c-2。这一点写进 crate 头注。

### 建议里采纳的

- `MIN_CASES` 地板 → **`assert_eq!` 强制触碰**（地板只维持到加第 11 条用例为止）；TS 侧那个常量删掉（已被全文件字节比较覆盖）。
- `#[serde(deny_unknown_fields)]` 四处 —— **加上的第一次运行就红了**（夹具头上的 `_` 注释字段被当未知字段拒），正好证明它是活的。
- **钉住「对拍的 TS 那一半还在」**：`include_str!` 那个 vitest 文件 + 断言它仍在调 `renderGoldenFixture()`。此前把它改名成 `.spec.ts` 就同时从 vitest glob 与 `npm test` 消失，两种语言可以**永远静默分家**。
- **把「新增共享 crate 要补 CI 三样」从散文变机检**（新 `shared_crate_registry.rs`）—— 这条纪律已经被违反过两次。遍历 `crates/*/Cargo.toml` 拿包名（不手写清单），三处缺一即红，另配抽取器自检与反向「僵尸引用」检查。
- 定级措辞两处订正：上游枚举补 **`/proc` 探针**（不是 manifest，我漏了）；补上**更硬的那条理由**（单引号包裹 + 两张表都拒全部元字符 ⇒ 只可能视觉冒充，不可能注入）。
- 精度订正：`trim()` 会把那六段里的**五段**在首尾位置吞掉 ⇒「多拒六段」只在**路径中间**成立（测试正是这么写的）。
