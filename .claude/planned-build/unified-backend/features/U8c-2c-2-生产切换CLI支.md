# U8c-2c-2 — 生产切换：`ccm 调用行`改由 Rust 渲染

- 工作区：unified-backend · 第六梯队 · 任务 #96
- 前置：U8c-2c-1（Rust 实现 + 16 条跨语言黄金串）
- 本件性质：**本工作区第一次真正切生产渲染路径。**

## 摸底：只切 CLI 那一支

`renderLaunchCommand` 有两支。实测后只切一支：

| 支 | 切不切 | 为什么 |
|---|---|---|
| **CLI**（`tryRenderCli` → `ccm …`） | **切** | 它是**真在跑的那支**（U8c-2b-0 摸底：装了 ccm 就直接 return）；Rust 侧已有实现 + 16 条黄金串 |
| **兜底**（`renderFallback` → 裸载荷） | **不切** | `container: tmux` 时它要外层 tmux 命令（`session-backend.ts`，151 行），而 `doc/INVARIANTS.md` §33b 写死了「搬它之前必须先回答三件事」（生产切到 daemon 没有 · attach 那条串归谁产 · daemonless 要不要能起会话）⇒ **U8c-3** |

## DoD

1. 新 tauri 命令 `render_ccm_launch(req) -> {ok, cmd, reason}`。
   **返回 tagged 而不是 `Result`**：「渲染不出来」是**诚实降级**不是错误，调用方要拿 `reason`
   去走兜底；用 `Err` 表达会和「IPC 真的失败了」混成一件事，而那两件事在前端走不同分支。
2. **wire 两侧对拍**：TS 那份是手写镜像，Rust 那边 `deny_unknown_fields`
   ⇒ 多送/少送一个字段会被**拒**，而那在生产里表现为「静默走兜底」—— 功能不变砖，
   但真正在跑的那条路悄悄换了、没人会发现。所以字段集必须有判据。
3. **接缝判据**：断言生产真的调的是后端（没有它，「换回 `tryRenderCli`」会让全部夹具/单测照常绿）。
4. 五处登记：`invoke_handler` · `parity_ledger`（LEDGER + 三个计数 + 不对称理由）· `ipc/commands.ts` ·
   `commands.vitest` 三处计数 · wire 类型文件。

### 不做什么

- **不切兜底那支**（见摸底 ⇒ U8c-3）· **不删 TS `tryRenderCli`**（降级为「只供夹具生成」，删在 U8c-3）。
- **不搬 ccm 探测**（`probeCcm` 仍在 TS，它有缓存；Rust 只收「能力集合」这个入参）。

## 工程审计结果（E）

- **这是本工作区第一条真正切过去的渲染路径**。切的是「真在跑的那支」，不是好切的那支。
- **兜底那支的阻塞是结构性的**，不是偷懒：§33b 那三个问题不回答就搬 `session-backend.ts`，
  等于把「attach 那条串归谁产」这类问题留给下一个人在删文件时现场发现。
- 账本：`launch.render-cli` 进 `parity_ledger`，理由 `NaturallyAsymmetric`（本地不经 IR）。
  S28 的产出点数**没变**（TS `renderFallback` 还在，只是 CLI 那支的生产消费者换了）。
- ⚠ **TS `tryRenderCli` 现在是「只供夹具生成」** —— 它仍被 `launch-cli-golden.ts` 调用，
  那正是跨语言对拍的来源。U8c-3 删它时要同时处置夹具生成器（S19 第五处的同一族问题）。
