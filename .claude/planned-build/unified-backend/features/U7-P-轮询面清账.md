## 一、摸底先翻了本轮的前提：U7 那条路线早就改过，而且已经做完了

本轮原定「U7 —— 读面合流（monitor 侧读面退役）」。查主计划变更记录，**2026-08-02 就改过路线**：

> 「U7 的路线改了：从「monitor 侧读面退役」改成「抽共享 crate」。**四项实测推翻原排期**。」
> …⇒ **U7a 若照原样做，本机会话在没人起 daemon 的机器上直接不可用 —— 不是风险，是确定的回归。**

而 STATUS 的进度表显示 **U7-1 / U7-2 / U7-3 / U7-4 / U7-5 / U7b / U7d 全部 ✅ 闭环**；
剩下的三项各有硬理由动不了：

| 剩余项 | 为什么不做 |
|---|---|
| U7a（jsonl tail） | **已降级登记** —— §0.1 自评「收益最低」，且「顺带验证本机 backend 管道」那个排期理由在 U5 收窄后已 void |
| U7c（用量） | ⚠ 踩 E42：`/usage` 解析**从未真机验证** |
| U7e（账号） | ⚠ **必须排在 U8 之后**（§1.5 的 Windows 窗口问题），而 U8 剩两刀卡在「ccm 契约谁做哪一半」 |

⇒ **「本轮做 U7」这个前提不成立**（铁律 4）。但摸底同时把那条**至今零登记**的轮询债量出来了 ——
那是用户点名过、且完全不阻塞的一件。⇒ 本轮做它。

## 二、缺口：daemon 半边零容忍，前端半边零机检

`no_timer_guard`（§41）的头注自己写着范围：

> 「**只钉 daemon crate。** monitor 侧另有自己的轮询纪律（那边有 UI 刷新、重连退避等**正当**
> 周期行为），把本护栏扩过去会立刻变成噪音 ⇒ **要钉那半得单独论证**。」

**那个论证到今天没人做过。** 于是：daemon 一个自己醒过来的构件都不许有（机检），
而前端每 10s 拉一次账号（无机检）；两个文件的头注里写着「本文件里不得出现
setInterval / setTimeout 轮询」——**散文纪律 = 没有纪律**。

## 三、论证：这一半该是**登记表**而不是禁令

前端确有**正当**周期行为（UI 重绘时钟、退避），一刀禁掉就是那条护栏预言的噪音。
所以钉的不是「不许有」，而是「**每一处都得说清它是哪一类、谁来退役它**」：

| 类别 | 含义 | 要求 |
|---|---|---|
| `ui-clock` | 只重绘已有状态、**不取数** | 说清它不取数 |
| `data-poll` | **真轮询** | **必须写明事件源在哪 + 谁退役它** |
| `wait-for-condition` | 等一个一次性条件（有上限） | 说清没有内核事件源可用 |

## 六、诚实边界（写在模块头注里）

- **查不了「没按 `poll` 命名的递归 `setTimeout`」** —— 那种形态在语法上与一次性延时无法区分。
  普查时正是靠 `pollTimer = setTimeout(…, pollMs)` 这个**命名**才抓到 `tabs.ts` 那一处。
  **比没有强，别读成证明。**
- **monitor 的 Rust 侧刻意不在范围内**：那边的 `thread::sleep` 大多是「等一个一次性条件」
  而不是节拍（`bind.rs` 的重试、`launch.rs` 的窗口等待…），逐条论证是另一件事。
  **如实登记为未做，不假装覆盖了。**
- **本轮没有消灭任何一处轮询** —— 三处 `data-poll` 的退役各归 U7e / U9b / U10，
  而 U7e 有 §1.5 的排期硬约束。**把「我以为有两处」变成「机器数出四个文件七处、每处有主」，
  就是本件的全部交付。**
