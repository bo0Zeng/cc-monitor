我此前（本会话早些时候）记的是：「加了新隔离项后 `share_items()` 会开始跳过它，但**不会拆掉
已存在的软链** ⇒ 净效果是『配置说隔离、现实还共享、`verify` 报错』三方不一致」。

**这条是错的。** 沙盒实测（假 `$HOME`，`init z` + `add b`，把 `settings.json` 加进

## 3. 一处对主计划的形态修订：`migrate` 被 `sync` 吸收

主计划 §3 账本第 10 行原写：「`migrate`：按**新旧声明**求差集，对每项调 `isolate`/`share`」。

**实测后否掉了**：**旧声明没有任何地方持久化**——`ISOLATE_SET` 只有"当前值"（配置文件 /
环境变量 / 内置默认三级），没有历史。所以"新旧差集"无从计算。

真正可做且语义干净的是：**让现实对齐当前 `ISOLATE_SET`**。而那**正是 `sync` 的职责**
（`verify` 今天就在报「隔离项 X 竟是 symlink(会串号!)」= 一条已被承认的不变量违反，
`sync` 的定位就是「幂等补链/**修断链**/修权限」）。

⇒ **不新增 `migrate` 命令**。迁移路径就是「改 `ISOLATE_SET` → 跑 `sync`」，
外加一个 `isolate <项名>` 做**定向**操作（只想动一项、不想让 `sync` 顺手把别的漂移也修）。
少一个命令名、少一处语义重叠。

## 4. 实现

### 4.1 `ISOLATE` 动词（`lib.sh`）

```
读共享文件签名(mtime.size) → bk_copy 备份目标 → 同目录 mktemp 写副本 → 复核签名未变(CAS)
→ **先 rm 掉软链** → mv -f 落位 → 自检(不再是软链 && cmp 内容一致) → 不符则 ln -s 回滚 + die
→ undo_restore 登记
```

四处刻意的细节，每处都有具体的失效模式在背后：

| 细节 | 不这么做会怎样 |
|---|---|
| **copy-then-unlink，绝不 MOVE** | MOVE 会把共享库那份搬走 ⇒ 只有第一个账号拿到文件、**其余账号的软链全部悬空**。共享库那份还要留作新账号模板（用户已批） |
| **`mv` 前先 `rm` 掉软链** | `mv -f tmp link` 会**跟随软链**把内容写到共享库去 —— 灾难性的**反向覆盖** |
| **CAS 复核签名** | 有活进程（比如正在跑的 Claude Code）在 `cp` 与 `mv` 之间写过共享文件 ⇒ 我们手上这份副本已陈旧。**宁可不动也不落一次陈旧覆盖** ⇒ 不落盘、die、让人重跑 |
| **自检 + 回滚** | 落位后若仍是软链或内容不符，立刻 `ln -s` 回滚成软链并 die（备份也在） |

**为什么对在用的会话不可观测**：同目录 `mktemp` + `mv -f` = `rename(2)`，**原子**；
路径**没有一个瞬间是不存在的**；且内容与共享库**逐字节相同** ⇒ 任何时刻任何一次读都拿到同样的字节。

### 4.2 `cmd_sync` 的分支（`cc-acct-iso`）

原来：`is_isolate || is_excluded || 共享库没有` → 一律 `RM`。
现在：`is_isolate` **单独一支** → 共享库有那份 ⇒ `ISOLATE`；真没有 ⇒ 才 `RM`（无内容可复制）。
`is_excluded` 与「共享库没有」两种情况的 `RM` **语义不变**。

### 4.3 `cmd_add` 认 `ISOLATE_SET`

新账号对每个隔离项，此前既没有软链（`share_items()` 跳过它）也没有实体 ⇒ **拿不到该文件**。
现在凡共享库里有那一份（= 模板）就 `ISOLATE` 成私有实体。

**`.credentials.json` / `.claude.json` 刻意排除**：身份必须由 `--from-credentials` /
`--seed-claude-json` 显式给，或由用户登录产生 —— **绝不从别人那儿悄悄复制一份身份过来**。
有断言钉住（`add **不**从别处复制身份`）。

### 4.4 断言地板搬进脚本自己

`run-tests.sh` 收尾加 `MIN_ASSERTS=197` + `[ "$T" -lt "$MIN_ASSERTS" ] && exit 1`。
**为什么必须有**：原来的退出码只看失败数 `$F` —— **`$F=0` 就 exit 0 ⇒ 一条不跑也会报绿**。
这补上了 gate-integrity 主计划 §2 的「同源」（地板写在套件自己这一处），
G-B 那条 CI 侧地板保留作**双保险**（脚本被整体换掉时它还在），同步提到 197。

**一处我自己的错，如实记**：地板初值我**口算**成 194（171+23），实测是 **197**（新增 26 条）。
已按实测值改正。方法论里那条「数字别口算、用门禁报的实测值」本轮又栽了一次。
