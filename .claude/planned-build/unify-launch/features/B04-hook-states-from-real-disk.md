# B04 前置：钩子三态的真实盘面（2026-07-28，只读读了 `~/.claude/settings.json`）

> 计划 §3 说三态是「已装 / 未装 / 装了但指向别的路径」，并提醒第三态"最容易被误报成已装"。
> 实测发现**方向反了**：真实盘面上最容易误判的是把一个**完全正确的安装**误报成第三态。

## 一、规范片段 vs 用户实际，功能等价但字符串不等

| 来源 | `SessionStart` 的 command |
|---|---|
| `shared/cc-bus/scripts/cc-bus-install.sh:48-49`（规范片段） | `cc-register >/dev/null 2>&1 \|\| true` |
| 用户 `~/.claude/settings.json`（**实际**） | `"$HOME/.local/bin/cc-register" >/dev/null 2>&1 \|\| true` |

| 来源 | `Stop` 的 command |
|---|---|
| 规范片段 | `cc-bus-stop-hook` |
| 用户实际 | `"$HOME/.local/bin/cc-bus-stop-hook"` |

两者**功能完全等价**（`~/.local/bin` 就在 PATH 上，且那两个软链正指向 cc-bus 的脚本）。
但字符串不等 → **任何做「与规范片段做等值比较」的实现，都会把这套正确安装报成
「装了但指向别的路径」**，然后建议用户去"修"一个根本没坏的东西。

这与 B03 那几个发现同源：**判据必须对着真实盘面校准，不能对着自己写的样板校准。**

## 二、据此收敛的判据（不做字符串等值比较）

对每个钩子（`SessionStart` → `cc-register`，`Stop` → `cc-bus-stop-hook`）：

1. 遍历该事件下所有 `hooks[].command`。
2. 从命令串里取**被执行的程序**：剥掉前导环境赋值、取第一个词、去引号、取 basename。
3. **basename 命中** → 认为"这条钩子存在"。再看它给的路径形态：
   - 裸命令（`cc-register`）→ **已装（走 PATH）**；
   - 绝对/`$HOME` 路径且**该路径存在**→ **已装（显式路径）**——正是用户当前状态，**不是问题**；
   - 绝对路径但**该路径不存在** → **装了但指向别的路径**（真正的第三态，要报）。
4. basename 一个都没命中 → **未装**。

**刻意不做**的判断：不比对重定向/`|| true` 这些尾巴（它们纯属风格），不要求顺序，
不要求它是该事件下唯一的钩子（用户完全可能同时挂着别的工具的钩子——实测该文件里
`SessionStart` 与 `Stop` 各只有一条，但这不构成假设）。

## 三、绝不写入（用户 2026-07-28 定调）

只读 + 诊断 + **生成待贴文本**。不写 `~/.claude/settings.json`。
理由不是保守：`cc-bus-install.sh` 第 3 行同样写着"只做可逆的本地安装：不改全局
settings.json、不 systemctl"——**两边一致，是这个生态的既定约定**，不是我的加码。

生成的待贴片段要给**两种形态**让用户挑：裸命令（简洁，依赖 PATH）与 `$HOME` 显式路径
（稳，与用户当前实际写法一致）。默认给后者——因为那是这台机器上被验证过能工作的形态。

## 四、边界情况（要有测试，不能假设文件干净）

- 文件不存在 / 不是合法 JSON / 顶层不是对象 → **宽容降级成"未装 + 说明原因"**，不抛。
  （同 `mcp.rs` 的「缺/坏 → None」精神。）
- `hooks` 缺失、或它不是对象、或某事件的值不是数组、或 `hooks[]` 项缺 `command` →
  逐层容忍，跳过坏的、不让一个坏条目吃掉整份诊断。
- `command` 是空串 / 只有空白 → 不算命中。
- 同一事件挂了多条钩子，其中一条是 cc-bus 的 → 算已装（不要求独占）。
