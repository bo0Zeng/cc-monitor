# B03 前置：真实脏数据实测（2026-07-28，直接读开发机 `~/.cc-bus/`，只读）

> 这份是 B03「喂脏数据不崩」测试的**输入来源**。计划 §1 原先记了三类，本次复核**订正了两处、
> 新发现一处**。全部是盘面实况，不是假想风险。

## 一、`spawned.tsv`：15 行里 **5 行畸形**（比计划记的"一行"多，但**不是多数派**）

计划原文说「有**一行**是 `x_y_cc\t/tmp/…/x⏎y\t…`」。实测：

```
好行(4 字段)=7   非空畸形行=5   真空行=3   总行=15
解析器实报 skipped=5（真空行按契约不计）
```

> **订正记录**：我最初写的是「坏行=8、53%、坏行是多数派」——**错的**。8 = 5 畸形 + 3 真空行，
> 而「空行不计入 skipped，否则 UI 虚报」恰恰是我自己在 `cc_bus.rs` 里立的契约。
> 写文档时我用的口径正是代码里明令禁止的那个。实际 5/15=33%（非空行口径 5/12=42%）。
> **设计结论（不能因坏行整体报错）不受影响**——7 条好行确实全解出来了；错的是记录。

两种不同成因，但同一个根因——**字段里含 `\n`，把一条记录劈成多行**：

| 行 | 字段数 | 成因 |
|---|---|---|
| 2–3 | 2 / 3 | **目录名**含换行：`/tmp/tmp.o6LGcLq9Qq/x` + `y` |
| 9–11+ | 0 / 1 / 0 | **任务文本**含换行：`背景:android-terminal(aterm,手机 SSH 终端 App)这边准备接进…` |

→ **对 B03 的含义**：按行 split 会解析出一堆畸形记录，而且**多数派是坏的**。
解析器必须「跳过并计数」，UI 如实显示「N 条无法解析」。**尤其不能**因为坏行多就
认为文件损坏而整体报错——7 条好记录仍要正常显示。

## 二、`inbox/`：垃圾 id 仍在，且**朴素字符集校验拦不住**（新发现，重要）

`--help.jsonl`（188 字节）与 `282.jsonl`（0 字节）**都还在盘上**——有人敲过
`cc-send --help`，`--help` 被当成了收件人。

**新发现**：我第一版校验写的是 `^[A-Za-z0-9_-]+$`，实测 **`--help` 通过了**——因为 `-`
就在字符类里，`[A-Za-z0-9_-]+` 完全匹配 `--help`。纯数字 `282` 同样通过。

→ **B03 的 id 校验必须额外拒绝前导 `-`**，理由与 `shared/ccm:360` 那条
`""|-*) die "非法 tmux 会话名（空或以 - 开头）"` 完全同源：id 会被拼进命令行，
`-` 开头会被下游当成 flag 解析。**照抄 ccm 那套判据，不要自己另发明一套。**

统计：`inbox/` 共 56 个 `.jsonl` + 28 个 `.jsonl.lock`。
**`.lock` 是合法锁文件，不是脏数据**——若把它们算成「非法 id」，UI 会报 28 个假错。
解析时必须先排除 `*.lock`。

## 三、`agents.tsv`：结构干净，脏在**陈旧**（与计划一致）

```
字段数 3 的行: 37 行（全部）   ← 结构上零坏行
最早条目: 2026-07-18（10 天前）
```

→ 这里的问题**不是**畸形，而是**登记 ≠ 在线**。计划 §2 批一「登记与在线分开呈现」
的设计是对的：`agents.tsv` 只证明它登记过，判在线要另查 `tmux has-session`，
那是第二次往返，放在用户点某一行的「检查」上，不默认全量查。

## 四、据此收敛的 B03 解析器契约

1. 逐行读，`\t` 切分；**字段数 ≠ 期望值 → 跳过并 `skipped += 1`**，绝不抛。
2. id 过校验：非空、**不以 `-` 开头**、只含 `[A-Za-z0-9_-]`、无控制字符（照抄 ccm:358-362）。
3. 时间戳解析失败 → 该行仍可显示，但标注「时间未知」，不因此丢整行。
4. 列 inbox 时**排除 `*.lock`**（机制：文件名后缀须**恰好** `.jsonl`；`KVM_cc.jsonl.lock`
   结尾不是 `.jsonl` 故自然被挡。**批一不实现这个 helper**——批一不读 inbox，为还没有的
   消费者留代码正是 R12/R15 反复拒绝的事；批二写 inbox 读取时再加，连同它的测试）。
5. 返回结构带 `skipped: usize`，UI 如实显示「N 条无法解析」而不是假装干净。
