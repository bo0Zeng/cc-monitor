# G3b — 本地拉起补账号注入（G3 的后半，第一步）

G3a 查清了「账号该是什么」，G3b 负责「怎么把它带上」。本轮做**后端那一半**。

## §1 为什么只有本地要补

| 路 | 能不能带账号 |
|---|---|
| **远端** `launch_remote_terminal` + launch IR | **能** —— IR 的 `account` 维度现成（`--account <name>` / `--base` / `export CLAUDE_CONFIG_DIR`） |
| **本地** `resume_history_session` → `launch_local` → `build_local_{ps,posix}_command` | **不能** —— 两个命令构造器都不注入 |

## §2 `None` = 账号 0 = **一个字都不注入**

与 IR 的 `--base` 语义对齐。这个选择有一个额外好处：

**既有那批「逐字节钉死输出」的测试全部传 `None` 后原样通过 ⇒ 它们就成了
「账号 0 = 旧行为」的守卫**，不必另写一条，也不必改任何断言。
（改断言是这类重构最容易悄悄放水的地方。）

空串与纯空白同样按账号 0 处理 —— 否则会产出半个前缀 `export CLAUDE_CONFIG_DIR=''; `，
那既不是账号 0 也不是任何账号。变异 R1 钉住。

## §3 校验**照抄** TS 侧，不重新发明

`validate_config_dir` 的判据逐条对齐 `src/shell-quote.ts:41` 的 `isValidConfigDir`：
非绝对路径 · `/` 本身 · 含 `/../` 或以 `/..` 结尾 · shell 元字符与引号 · 控制符（C0/DEL/C1）·
可欺骗 Unicode（零宽 / 双向控制 / NBSP / BOM）。

**为什么不自己想一套**：那边已经因为账号隔离审计 D7（extraEnv key 无校验）收紧过一轮。
这条产物会进 shell，宽容一格就是注入面 —— 抄一个被审计过的判据，比现想一个强。

**非法即 `Err`，绝不「清洗后使用」**。变异 R2 钉住。

## §4 前缀必须在**最前面**

`export CLAUDE_CONFIG_DIR=…; <cmd>` —— 拼到后面就变成「先跑 claude 再 export」，
账号完全不生效，而命令看起来是对的。变异 R3 钉住（把 `prefix` 从拼接里摘掉 → 红）。

## §5 变异（退出码 + 落地核查）

| # | 变异 | 结果 |
|---|---|---|
| R1 | 空串不再等价于账号 0（产出半个前缀） | 红 |
| R2 | 校验放水（接受注入串） | 红 |

脚本的模式串没匹配上 ⇒ 报「0 条红」。**那是无效结果不是绿** —— 按实际文本重做后见红。
（同一形状本轮已栽第三次：变异脚本的模式串要在**改完之后**用 grep 计数确认。）

## §6 边界：起**新**会话不继承账号

`new_local_session` 显式传 `None`。「在这个目录起个新会话」的语义就是从头开始，
不是分叉 —— 继承账号会让「新开一个」变成「悄悄用上一个会话的身份」。
