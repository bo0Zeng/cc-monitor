| | 现状 |

### §0.2 ★ 我们的落盘格式与官方 `/branch` **一致**（实证，本计划的地基）

**样本**（只读结构字段，未把任何对话内容带进本仓）：

- **两份确定原生的 fork**：`0473c3a0`（07-03）、`fe4aad07`（07-05）。
  两者都**早于 F62 合入的 07-16** ⇒ 只可能是 CC 自己产的。
- **一条三代 fork 链**：`AuthorKit27` 的 `a40059e8 → 7c2a26d6 → 4f3fba62`（07-29 ~ 07-31）。
  每代**独立文件**，`forkedFrom.sessionId` 精确指向上一代 —— 所以父会话照样能 resume。

**算法指纹（决定性）**：

| | `0473c3a0` | `fe4aad07` |
|---|---|---|
| 相邻成链（每条的 parent 就是前一条） | **1401/1401** | **117/117** |
| 首条 `parentUuid` | `null` | `null` |
| 复制段在源文件里的**行号跨度** | 1964 行 | 170 行 |
| **实际取了** | **1402 条** | **118 条** |
| **跳过的旁支** | **562 条** | **52 条** |

**跳过旁支把「线性文件切片」排除了** —— 若官方是 `transcript[:cutoff+1]`，那 562 条落在
区间内的记录会被一并带走。⇒ **官方 `/branch` 走的就是祖先回溯，与我们相同。**

**逐字段一致性**：

| 维度 | 官方原生 fork | 我们 |
|---|---|---|
| uuid | **原样保留**（118/118、1402/1402 能在源里找到） | 一样 |
| timestamp | **不改**（逐字相同） | 一样 |
| `slug` / `sourceToolAssistantUUID` / `agentName` | **照样带着**（源里 5274 / 1553 处） | 一样 |
| 复制段的记录类型 | **只有 `assistant` / `user` / `attachment` / `system`** | 一样（祖先链天然如此） |
| 不带 uuid 的旁挂记录（`mode` / `permission-mode` / `ai-title` / `last-prompt` / `file-history-snapshot` / `queue-operation`） | **一条不带** | 一样 |
| `logicalParentUuid` | 复制段里那一条的目标**既不在复制段内、也不在源会话里** ⇒ 官方自己不保证这条边 | 不跟、不 remap、不报错 |
| 根的 `parentUuid` | `null` | 一样（我们显式置 null） |

⇒ **落盘格式无需任何改动。** G0 的任务是把这个结论**钉成机检**，不是改行为。

### §0.3 官方 SDK 有 `fork_session`，但我们不用它

`claude-agent-sdk 0.2.128` 的 `fork_session(session_id, directory, up_to_message_id, title)`
（`_internal/session_mutations.py:240`，在 `__all__` 里，是公开 API）确实做同一件事。**三条不用的理由**：

1. **它是 Python。** cc-monitor 是 Tauri（Rust + TS），出 `.exe`/`.msi`/`.deb`，**零 Python 运行时依赖**。
2. **远端更不可能。** 我们的拓扑是 monitor 在 Windows、会话在远端 Linux ⇒ 它得跑在 daemon 里，
   而 **daemon 是静态 musl 二进制**。用户已拍板远端走 daemon 命令 —— 两条路互斥。
3. **它与官方 TUI 落盘不一致**：SDK 会 remap 全部 uuid、清 `slug` 等字段、改末条 timestamp、
   且 `up_to_message_id` 是**线性切片**。这些是 SDK 自己的选择，**不是 CC 的落盘规范**。

> **⚠ 给未来的自己和任何接手者：别拿 SDK 当规范。**
> 规划本区时我正是这么错的 —— 照着 SDK 列了六条「我们的缺口」，被 §0.2 那批真机语料**全部证伪**。
> 判据只有一个：**CC 自己落在盘上、`claude --resume` 能读回去的那个格式**。

### §0.4 两套机制别混：ESC 回退 ≠ `/branch`

| | ESC 回退（双击 ESC 重说） | `/branch` |
|---|---|---|
| 产物 | **同一个文件**里长出第二条路 | **新文件** + `forkedFrom` |
| 表现 | 旧路径变 off-main（`branching.ts` 建模的就是它） | 父会话完好，可独立 resume |
| 实测样本 | `project/asd`：单一 sessionId、5 个根、**84 个分叉点**、零 `forkedFrom` | `AuthorKit27` 的三代链 |

用户说的「得 ESC 回去、这样就破坏当前会话」指的是**左边那套**：活跃指针挪走了。
**我们这条路（复制成新文件 + 另起一个进程）能做到「两条都活着」**，
而 ESC 那套结构上做不到 —— 这是本功能的产品价值所在。

## §2 目标形态

```
用户在任意一条消息旁点「⑂ 分叉」
        │
        ├─ 本地会话 ── monitor: fork_records()（Rust 纯函数）→ 写新 jsonl
        │
        └─ 远端会话 ── daemon --fork-session（远端本地读写）→ 回新 sid
        │
        ▼
   读原会话的启动参数（账号 / 是否 tmux / cwd）
        │
        ▼
   用同一套参数起**新**会话（只换 sid + 换 tmux 名）
        │
        ▼
   原会话照跑不动、tab 不变灰；新会话另起一个 tab
```

**「不杀旧会话」的准确含义**（用户拍板）：不走 CC 的 `/branch`（同一 pidfile 原地换 sid
= S0 那个 `Superseded`），而是**复制 jsonl + 另起一个进程** ⇒ **两条都能继续聊**。

## §4 `readonly_guard` 怎么改（同时解掉 BACKLOG E50）

**不删、不放宽成「随便写」，而是把不变量重新表述准确。**

那条护栏的**真实意图**从来不是「daemon 不许碰文件系统」，而是
**「daemon 不许改动用户既有数据」**。今天用「全面禁写」来近似它，因为此前 daemon 确实
一个字都不用写。要加的能力恰好落在这个近似的**误差**里：

> 用 **`O_EXCL` 新建一个此前不存在的文件**，不修改、不覆盖、不删除任何既有文件。

⇒ 护栏改成两层：

1. **默认层不变**：daemon 生产源码仍不得出现那 11 条写模式。
2. **白名单层**：**恰好一个**模块（如 `fork_write.rs`）可写，且对它另加**更强**的断言 ——
   只准 `O_EXCL` 新建，不得出现 `remove_*` / `rename` / truncate / 追加写，
   且路径必须落在 projects 目录下。

**这比今天更强而不是更弱**：今天护栏对「daemon 将来要写盘」没有任何设计，一旦有人要写
就只能整条删掉；收窄之后，写的能力被钉死在一个可审计的洞里。

**同时更新** `doc/INVARIANTS.md` 里 I7 的措辞：从「daemon 只读」改成
「daemon 不改动既有数据；新增文件须 `O_EXCL` 且限于白名单模块」。

## §5 已知风险

1. **账号来源不确定（最高）。** `TMUX_LS_FMT` 不含账号且**不许改**。
   `--session-accounts` 是现成答案，但它按 **PID** 扫 `sessions/<PID>.json` ——
   对**已退出**的历史会话可能答不出。⇒ G3 的第一步是**查清**，不是设计；
   答不出就降级成「分叉时让用户选一次」，**不猜**。
2. **实时会话的 jsonl 还在增长。** 祖先回溯只依赖被选节点及其祖先（都已落盘），
   理论上安全，但要有测试钉住「分叉过程中源文件继续增长，产出不受影响」。
3. **daemon 首次写盘。** 除护栏外还要想清并发（两个 monitor 同时分叉同一会话）、
   磁盘满、远端 projects 目录权限。`O_EXCL` 挡住覆盖，但错误要能回到 UI（§12 可见失败）。
4. **`tabs.ts` 是主平台主路径。** G4 动它。用户已解禁，但仍是高风险面。
5. **G1 的共享方式选错会留长期债。** daemon 不在 workspace 是**刻意的**（Windows CI）。
   三条路各有代价，Phase B 要拿实测说话。
6. **CI 目前是红的**（BACKLOG E67，连红两个版本）。G2 要动 daemon 侧护栏，
   开工前最好先把 CI 弄绿，否则分不清是不是自己弄红的。
