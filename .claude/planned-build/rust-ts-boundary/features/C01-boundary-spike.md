## 1. 目标（一句话）

改 Rust，`npx tsc --noEmit` 必须报错。今天不会。

## 2. 选中的命令：`get_data_paths`

| 判据 | 为什么它满足 |
|---|---|
| 有 `camelCase` 重命名 | `DataPathInfo`（`data_paths.rs:23`）与 `DataPathsResponse`（`:41`）**都带** `#[serde(rename_all = "camelCase")]`。**这是选它的首要理由**——`ts-rs` 认 serde 属性是选它而非 `typeshare` 的主要依据，必须在样板里就验 |
| 嵌套结构 | `DataPathsResponse` 内含 `DataPathInfo` ⇒ 验嵌套导出 |
| 主流返回形态 | `Result<DataPathsResponse, String>`（本仓几乎所有命令都是这个） |
| TS 消费点少且正是要替掉的形态 | **恰好一个**：`src/settings/data-section.ts:87` `await invoke<DataPathsResponse>("get_data_paths")` —— 手写类型参数，一改 Rust 就静默失配 |
| 不在冲突区 | 不是 `accounts.ts`（归 account-zero）/ `sftp/paths.ts`（归 C03）/ `launch-plan.ts`（本区不碰） |
| 低风险 | 只读探测（`collect` + `spawn_blocking`），无写盘、无远端、无 tmux |

## 7. 代码审计结果（Phase D）

**对抗性审计已发出（1 个综合 agent，低风险档），结果待收。** 以下是**我自己**在实现过程中
撞到并已处置的五条，交给审计独立复核（**别采信我的结论**）：

### 实现中发现并已修的（三条，都是「类型撒谎」）

1. **`ts-rs` 不认 `skip_serializing_if`** ⇒ 默认生成 `sizeBytes: bigint | null`，
   而该字段带 `#[serde(skip_serializing_if = "Option::is_none")]`，`None` 时**字段在 JSON 里
   整个缺席**，TS 侧收到 `undefined` 永不为 `null`。**类型声明了一个永不出现的 null。**
   → 加 `#[ts(optional)]`。
2. **`ts-rs` 默认把 `u64` 映射成 `bigint`，而那对 Tauri 的 JSON IPC 是错的**。
   **证据来自仓库自身**：改动前 `data-section.ts` 直接 `formatBytes(info.sizeBytes)`，
   而 `formatBytes` 内有 `(n / 1024).toFixed(1)` —— `bigint` 没有 `.toFixed`，
   真是 BigInt 的话生产里早就 `TypeError`。所以那是**朝另一个方向撒谎**。
   → 加 `#[ts(type = "number")]` + 上限论证（展示文件大小，2^53-1 ≈ 8 PB）。
   **这不是预判 C03 的策略**：策略（哪些字段该走 string/bigint 过线）仍归 C03；
   但**类型不许与运行时不一致**，所以这一处在 C01 修掉。
3. **守卫第一版自己抓自己红了两次**：
   ① 没剥注释 ⇒ 生成物 JSDoc 里含有我写在 Rust doc comment 里的 `sizeBytes: bigint | null`
      那串字，被当成类型判据；
   ② **有一条断言本身是错的** —— 它禁 `invoke<DataPathsResponse>` 那个形态，
      而现在 `DataPathsResponse` 已经是生成的类型，那个形态完全正确
      （类型化包装层是 C04 的事，C01 明写不建）。**禁错了东西 = 假红 = 守卫会被人关掉。**
   → 剥注释（两侧都剥 + 反向自检防剥过头）+ 把断言改到真正的性质上（禁本地手写 interface）。

### 登记为发现、未在 C01 修（一条）

4. **`kind` 字段被放宽**：Rust 是 `String`（doc comment 说 `"file" | "dir"`），
   改动前手写 TS 是联合类型 `"file" | "dir"`，生成物是 `string`。
   ⇒ **从 Rust 生成会「丢掉」手写 TS 额外加的类型信息。** 正确方向是让 Rust 变成更严的源
   （改 enum，序列化后字符串不变、行为等价），**但那是类型收紧、不属于 C01 范围**。
   **这一条是 codegen 的一般性风险，不只是这个字段**：C04 全量迁移时会撞到一批。

### 顺手验掉的一条风险（幂等性）

5. **`cargo test` 会重新生成 `src/generated/`** ⇒ 担心 CI 里跑测试让工作树变脏、
   使 C05 的「生成物必须最新」门禁误红。**实测：生成物入 git 后重跑 `cargo test`，
   `git diff --exit-code -- src/generated/` 为空 ⇒ 幂等，C05 立得住。**

### Phase D 审计闭环（2026-07-29，1 个综合 agent，74 次工具调用 / 约 26 分钟）

审计做了 **8 次变异 + 2 次临时探针**，全部还原（7 个受审文件 md5 与审计前逐个相同）。
报了 **2 阻塞 + 4 重要 + 8 建议**。**逐条独立复现后的处置**：

#### 阻塞 1（技术指控成立，**严重性我不认**）：guard 4 第三条断言是安慰剂

它用**裸 `read()`** 读 Rust 文件，而我自己的 doc comment 里就写着 `` `type = "number"` ``
这串字（该文件里出现两次：注释一次、真属性一次）。独立复现：

```
裸 read 含 type="number"：   true    ← 被注释喂饱
剥注释后含 type="number"：   false   ← 用 code() 才会正确变红
```

**但那个变异仍然被同一个测试抓到了**——红的是第 1 条（生成物断言 `sizeBytes?: number`）。
所以它声称的保护实际由旁边两条提供，**不是审计说的「唯一的长期保护」**。
→ **按「重要」修**（用 `code()`），因为修它的真实价值在**另一格**：
「改了 Rust 属性但**没有**重新生成」——那一格生成物还是旧的、第 1 条是绿的。
**变异验证**：删属性 + 不重新生成 → 现在红，且红的正是 Rust 源那条断言。

这是本会话「剥注释」这个形状的**第三次**，前两次都在 TS 侧，这次是**忘了剥 Rust 侧**。

#### 阻塞 2（成立）：`.gitattributes` 写了一条不存在的保证

原文写「改了会被 generated-boundary-guard 抓到」。审计实测：手改生成物、
甚至插一个 Rust 侧根本不存在的字段 ⇒ **5 条守卫 + tsc 全绿**。
→ **已修**：删掉那句假保证，改成如实说明「手改目前只靠人工纪律，真正的检查是 C05」。
守卫头注也补了一节「本守卫的已知盲区」，把两个抓不到的场景写明。

**这一条我认严重性**：本工作区的整个论点是「把人工纪律换成生成物」，
而往配置文件里写一条假保证，正是被替掉的那个东西——下一个人会信它。

#### 重要 1（成立，**已改执行顺序**）：CI 里这条链没有牙

CI 的 `rust` job（跑 `cargo test`）与 `frontend` job（跑 `tsc`）是**两次独立 checkout**：
重新生成的产物在前者里被丢掉，后者对着**已提交的**生成物做类型检查。
审计变异实测：serde-rename 一个字段而**不重新生成** ⇒ cargo 绿 · tsc 绿 · 守卫绿 ·
npm 819 全绿，**而生产里 IPC 发 `labelStaleProbe`、TS 读 `.label` 拿 `undefined`、UI 标签变空**。
**失效模式不是「没门禁」，而是「所有现有门禁都保持绿」。**

→ 两处处置：
1. **C01 加 `npm run check:types`**（`gen:types && tsc --noEmit && git diff --exit-code -- src/generated/`）
   ——把「同一棵树里先 regen 再 tsc」变成可脚本化的东西。**实测**：同一个变异下
   旧门禁全绿而 `check:types` 红。
2. **把 C05 从执行顺序 #4 提到 #2**（`planned-build/README.md` 已改，附理由）。
   否则这个洞会被复制到 127 个 struct。

#### 重要 2/3（成立，已修）：两条断言在算术上/文本上不可能失败

- `expect(checked).toBe(2)` 遍历一个**硬编码二元数组**自增 ⇒ 不可能不是 2，
  而注释写着「加了第三个文件会红」。审计实测：塞一个手写文件 → 5 绿。
  → 改成 `readdirSync` + `toEqual([...])`。**变异验证**：塞文件 → 红。
- guard 2 的正向断言 `toContain("sizeBytes")` 同样被 JSDoc 喂饱（该串在生成物里出现两次，
  一次在散文里）⇒ 字段改名后依然绿，承重全落在 `not.toContain("size_bytes")` 上。
  → 改用 `code()`。

#### 重要 4（成立，已修）：`ts-rs` 进了生产依赖

→ 移到 `[dev-dependencies]` + `#[cfg_attr(test, derive(ts_rs::TS))]`
（导出本来就走 `cargo test`）。**验证**：`cargo tree -e normal -i ts-rs` → `nothing to print`。
理由：codegen 工具不该进发布二进制，而**这是个会被复制 127 次的策略决定**，现在定最便宜。

#### 建议里采纳的（S1/S2/S3/S5/S6/S7/S8）

- **S3 最有价值**：guard 3 原本把一条**通用性质**写成了单字段字面量断言。
  改成扫源码——只查带 `ts_rs::TS` 派生的 struct，断言每一处 `skip_serializing_if`
  都配了 `ts(optional)`，计数自检 `== 1`。**它同时杀掉了阻塞 1 那一类**，且能跟着 C02/C03 长大。
  **变异验证**：去掉 `ts(optional)` → 红。
- **S1**：把「`../../` 里有一级是幻影目录 `bindings/`」的机制写进 `data_paths.rs` 注释
  ——**我第一次写成 `../src/generated/` 落错地方就是因为不翻 ts-rs 源码推不出来**。
- **S2**：删掉 `toContain("2^53-1")` 那条散文断言（有人把它重排成 `2^53 - 1` 就假红）。
- **S5**：`eslint.config.js` 忽略 `src/generated/**`（实测 7 problems = 基线，未新增）。
- **S6**：主计划与 C01 §6 里「生成物加 `// @generated`」与实现矛盾 ⇒ 全部改准

#### 审计给出的比我更硬的证据（记下来，因为我原来的论证较弱）

`#[ts(type = "number")]` 这个决定**结论对，但我给的证据是现象级的**：
「`formatBytes` 里有 `.toFixed()`，真是 BigInt 早就 TypeError」只证明**今天不是** bigint。
审计找到了原理级的：`tauri-2.11.2/src/ipc/mod.rs:181-183` 的
`impl<T: Serialize> IpcResponse for T` 走 `serde_json::to_string(&self)` ⇒ 线上是 **JSON 文本**，
而 `JSON.parse` **永不产出 BigInt** ⇒ 命令返回值**在原理上不可能**以 BigInt 到达 TS 侧。
另有仓内同向先例：`usage.rs:24-27` 的 `TokenUsage` 四个 `u64` 跨边界，
TS 侧 `views/usage-pivot.ts` 声明 `number` 并直接做算术；全仓无 BigInt。
→ 两层证据都已写进 `data_paths.rs` 的注释，并标明哪层强哪层弱。

#### 一处措辞订正（我写错了因果链）

注释初版说「不加 `optional` 会得到**必需且可为 null**」。实测：在 `type = "number"`
同时存在时是 `sizeBytes: number`（必需、**不**可 null）；`bigint | null` 只在两个属性
都缺席时出现。**两个都是谎，但是不同的谎。** 已改准。
（另：`ts(optional = nullable, type = "number")` 实测也产出 `sizeBytes?: number`
——type override 吃掉 nullable，那条逃生路不存在。）

#### 审计独立复核确认「做对了」的

`#[ts(optional)]` 的必要性（逐字节验序列化产物 + 查 `ts-rs` 源码的 `maybe_omitted && has_default`
兜底条件）· **「无运行时行为变化」是实测不是论证**（摘掉 derive 与两个属性重跑同一探针，
两种输入的 JSON **完全相同**——`derive(TS)` 不触碰 `Serialize`）· 幂等性/无脏树独立复现
（含 `.gitattributes` 的 `* text=auto eol=lf` 覆盖生成物 ⇒ Windows CI 无 CRLF 脏树陷阱）·
变异 B 独立复现 · **guard 5 有真价值**（正向对照：把手写 interface 加回来 → guard 5 红而
`tsc` 0 错 ⇒ 它是「已接线/已拆线」之间唯一的东西）· 范围符合计划（9 文件，`e2e/` 0 行）。

#### 审计的 S4 补了一个我没查的代价（`kind` 放宽）

唯一消费点是 `data-section.ts:184` 的 `` `kind-${info.kind}` `` CSS 类名，
而 `styles.css` 只定义了 `.kind-dir`/`.kind-file` ⇒ 那个联合类型保护的是一个**CSS 类名耦合**，
现在类型层不设防（Rust 加第三个变体 → 图标静默消失、零编译错）。
**但没有任何代码失去真实检查**（无穷尽 switch、无 Record 索引），
而且改动前那个 `"file" | "dir"` 本身是**未经证实的收窄**（Rust 是 `String`）。
⇒ **C01 没有删掉一个可靠的检查，它删掉的是一个谎**，登记不修是对的。
**追加一条给 C04**：等 Rust 改 enum 时，顺手把 CSS 类名穷尽性也接上。
