## 2. 结论：C04 必须拆，理由是它违反 planned-build 自己的粒度准则

planned-build 的「功能粒度准则」原文：
> 一个「功能」应能在一份 feature 计划里讲清、**几步内实现完**、有独立可验证的 DoD。
> 太大 → 在主计划里拆成多个功能。

C04 当前的范围是 **63 个 struct + 119 个命令签名 + 161 个调用点**
——**比 C01+C02+C03 加起来还大**（那三个合计：14 个生成物、约 12 处调用点替换）。
一份计划讲不清，也没法「几步内实现完」。

**而且它有一个今天就到不了的成功标准**：主计划 §0.1 的
「全仓 `import { invoke }` 从 29 个文件降到 1」——**`tabs.ts` 单独占 15 处调用点，
而「不碰 `tabs.ts`」是本会话在册的红线**。不松那条红线，这个标准结构性达不到。

### 拆法（四个功能，各有独立可验证的 DoD）

| ID | 功能 | 独立 DoD | 依赖 / 阻塞 |
|---|---|---|---|
| **C04a** | **类型化 `invoke` 包装层 + 钉死 119 个命令** | 包装层存在且**至少一个模块**改用它；「钉死 119 个命令名」的守卫（把今天只覆盖 3/119 的白名单扩到 119）；变异：删/改一个命令名 → 红 | 无 |
| **C04b** | **两处已登记的内联字面量** | `main.ts:744` 的 `ActiveSessionPayload` 换成生成物 + `tabs.ts:1632` 的 `SessionActivityPayload`（**后者卡红线**） | **`tabs.ts` 红线** |
| **C04c** | **`JsonlLine`/`JsonlBatch`** | 两个 payload 生成；`seq: u64` 用 C03 的策略；`message` 用逃生口 `#[ts(type = "import('../cards').JsonlRecord")]`；**当场暴露的 4 处 `cards/index.ts` 缺口如实登记不顺手修** | C03（**已解除**） |
| **C04d** | **按模块分批迁移剩余 63 个 struct + 调用点** | 每批一个模块、一个 commit、一次全门禁；`import { invoke }` 文件数逐批下降 | C04a；`tabs.ts` 那批卡红线 |

**为什么 C04a 先做**：包装层与守卫是**机制**，C04b/c/d 都在它上面走。
先建机制再批量迁移，避免 63 次迁移各自决定「怎么调 invoke」。

## 3. C04a 的计划（本轮要实现的就是这个）

### 3.1 DoD

- [ ] **步骤 1 先定「返回值没人用类型的命令」怎么办**——C03 给出的答案是保持裸 `invoke`
      （不为假想消费者生成），但 C04a 面对 119 个命令**需要一条成文规则**并写进主计划 §5
- [ ] 建**手写的**类型化 `invoke` 包装层（`ts-rs` 不生成命令签名，见主计划 §8）
- [ ] **至少一个模块**改用包装层（选调用点少、类型已生成的那个做样板）
- [ ] **钉死 119 个命令名的守卫**：Rust 侧 `#[tauri::command]` 的 fn 名（剥注释后递归全仓抽取）
      ↔ `invoke_handler` 注册表 ↔ 包装层。计数自检用等号
- [ ] **变异验收**：① 删一个 `invoke_handler` 注册项 → 守卫红；
      ② 改包装层里一个命令名的字面量 → 守卫红。两次都先 diff 确认落位 + 确认编译得过再判色
- [ ] 反向自检：不变异时全绿
- [ ] 全门禁绿且数字不降（基线：cargo 550 · npm 821/54 · clippy 0 · tsc 0 · C05 门禁 rc=0）
- [ ] 8 套真机套件全绿、条数与基线一致

**明确不做**：不迁移 161 个调用点（C04d）· 不碰 `tabs.ts`（红线）·
不碰 `JsonlLine`/`JsonlBatch`（C04c）· 不生成剩余 63 个 struct（C04d）· 不改 `ci.yml`

### 3.2 守卫的形状（延续 C01/C02/C03 那两条的经验）

三条已被变异打磨过的经验直接套用：
1. **打在源上**（C03）：从 Rust 源抽命令名，不从生成物或包装层单侧断言。
2. **剥注释，两侧都剥**（C01/C02/C03 各栽一次）：本轮**我自己又栽了一次**
   （注释里提到 `#[tauri::command]` 被当成声明）——抽取器必须剥注释。
3. **计数自检用等号**（C02 时它抓到我新逻辑的 bug，C03 时抓到假红）。

**一条不能写的断言**：「每个命令都必须经过包装层」——C04a 只迁一个模块做样板，
其余 118 个还走裸 `invoke`，写了就是假红。范围该等于**性质**的范围。
