## 1. 抽象的**具体收益**（不止去重——去重本身不足以证成抽象）

实测发现四处「读回比对」**语义并不一致**，其中本机侧那份明显更弱：

| 处 | 比什么 | 失败时 |
|---|---|---|
| `profile_installer.rs:242`（写入） | **只比长度** `written.len() != updated.len()` | 从备份恢复 |
| `profile_installer.rs:305`（剥离） | **只比长度** | 同上 |
| `sftp.rs:729`（远端 ccm CLI） | **比内容** `cli_back != CCM_CLI_SCRIPT` | 报错，不动 profile |
| `sftp.rs:767`（远端 profile） | **比内容** | 回滚原文件 |

**本机侧只比长度 = 同长度的损坏静默放过**（字节翻转、编码变形、CRLF↔LF 等长替换）。
而 `~/.bashrc` / `$PROFILE` 写坏的后果是用户下次开终端就炸。

→ **T01 的第一个可验证收益：统一写入器把本机侧从「长度比对」升级为「内容比对」。**
这条要有一个**会红的测试**：构造一个"长度相同但内容不同"的写后状态，断言旧实现放过、
新实现拦住。**不是重构完跑一遍原有测试就算数**——原有测试挡不住这个，否则它早就红了。

## 9. 第 4 步落地记录（远端三处，2026-07-28）

### 判断：远端侧**没有「升级」可做**，但有两个真问题

三处远端（`sftp.rs:660/729/767`）**本来就是内容比对 + 回滚**，已是四者中最强的一档。
强行套一层 async 写入器是**纯管道、零行为收益**——按本工作区的纪律，抽象要有收益才建。
所以第 4 步不做"套壳"，只做实测发现的两件事：

**① `unwrap_or_default()` 把「读不回来」和「文件是空的」混为一谈（已修）**
原先读失败 → 变成空串 → 与期望不等 → 报「读回内容与期望不符」。于是 SSH 抖一下会被
报成"内容写错了"，**把用户往错误方向引**。三处一律改成先判 `None`，单独报
「写后读不回 X（无法确认写对了）」再回滚。这与 `write_and_verify` 里那条
「读不回来 ≠ 写对了，也要回滚」是同一条判断，只是这里手写（async 走不了那个同步签名）。

**② ccm CLI 那处写坏后不回滚，而另两处回滚（登记未改，但把后果说清了）**
它自己的注释写着「CLI 是可执行文件，写坏比 profile 写坏更危险」，这让缺失的回滚更刺眼。
不改的理由：部署前**没有取旧 CLI 的备份**，要回滚得先多一次读往返——那是这条部署路径上的
**行为变更**，而它被 12 条 print-parity + 15 条 acceptance 真机断言盯着，风险/收益不划算。
→ 改法取"如实告知"：错误措辞加上「**但 `~/.local/bin/ccm` 已被写入且内容不对，
请手动删除或重新部署**」。**不静默留一个坏 CLI 在远端还只说"未改动 profile"。**

三处的判定统一走 `verify_readback`，顺带把错误措辞升级为具体差异（是长度不符还是等长损坏、
首个差异在第几字节）——原来的「读回内容与期望不符」对排障毫无帮助。

### 覆盖的诚实说明（**不谎称已守**）

这四条新分支是 `async` + 真 SFTP，**单测走不到，本轮也没有为它们新增可红的测试**。
它们与 `sftp.rs` 既有的写入路径处境相同：靠真机 e2e 与人工部署覆盖。
被守住的是 `verify_readback` 这个**判定本身**（纯函数，9 项测试，含"等长损坏必须拦下"）。
→ 登记为 **P6**：远端写入路径缺可红的失败注入测试。真要补，需要一个能伪造
`read_optional` 返回值的接缝（把 sftp 操作抽成 trait），那是独立的一步，不塞进本功能。

## 10. 第 5-6 步落地记录

### 第 5 步：`ToolSpec`——「探测」这一项过不了自己的判据

计划 DoD 写「五个正交关注点：源/落点/探测/装升卸/配置面申报，每项至少被两套工具实例化」。
动手时逐个数真代码，**「探测」不合格**：ccm 是文本自报、cc-acct-iso 是内容指纹、
daemon 是带内协议帧、PowerShell 是扫围栏——**四种机制彼此不兼容且各只有一个使用者**，
做成 enum 就是四变体各一用户的上帝结构。

→ **机制留在各工具，结果统一成 `ProbeStatus`**。注册表只消费结果、不规定怎么探。
这条边界顺带满足账本的「不改 `shared/ccm` 本体」——"只消费它已有的输出"天然合规。

配一条纪律测试把「每字段 ≥2 实例化」变成门禁。变异四条全红。

### 第 6 步：结构性扫描抽成可复用形式

`sftp.rs` 那段是本仓质量最高的一处防线，抽取时**不得降级**。它的四个要件逐条内建进
`structural_scan.rs`：

1. **枚举**每一处结构特征（不是找几个固定字符串）；
2. **逐个断言**同一性质；
3. **计数自检**——扫到 0 处 = 扫描器失效，必须红。**这一条内建在 `require()` 里，
   调用方想忘都忘不掉**（本会话我写坏的四条守卫里"恒绿/空转"占两条）；
4. **钉死逃生口**——被放行的间接变量（`$t`）其定义必须逐字钉死。**这条最容易漏**：
   不钉的话 `$t` 能被改成裸值，前三条照样全绿而防线已经没了。

**它天然是白名单**：枚举每一处出现并要求它们**都**满足好性质，新增的出现自动纳入。
这正是本轮新纪律（结构性守卫优先白名单）的最好例子，也是固定 needle 永远做不到的。

**`sftp.rs` 真的改用了它**（不是抽了摆着——B03 阻塞-2 刚踩过"抽了 `build_online_cmd`
却没接上"）。**用两条历史绕过手法验证**：
- 把 `$t` 定义改成裸值 → **红**（要件 4）
- 把某处 `-t` 改回裸目标 → **红**（这正是 F04 的 D 审计当年证明固定 needle **空转**的手法）

sftp 13 项测试行为等价，六套真机套件全绿。
