## 2. 判据落在「周期性唤醒」，不是落在「出现过 `Duration`」

**这是本护栏设计上最要紧的一点。** 先实测全 crate 生产段的 `Duration`/`Instant` 用法：

```
watcher.rs:49   use std::time::Duration;
watcher.rs:666  Duration::from_millis(DEBOUNCE_MS)
```

只有两处，而 `DEBOUNCE_MS`（100ms）是 **notify-debouncer 的事件合并窗口** ——
它**不产生唤醒**，只决定「同一批文件事件攒多久再一起交付」。去掉它 inotify 照样推事件，
只是更碎。**它是 `Duration`，但不是定时器。**

若把判据写成「不许出现 `Duration`」，就得为这一处开豁免；豁免一开，下一个人加节流常量时
顺手也塞进豁免里 —— 护栏从「防退化」变成「防不了但很吵」。

⇒ 拆成**两条互补的断言**：

| 断言 | 禁什么 | 防的是 |
|---|---|---|
| `daemon_production_code_has_no_periodic_wakeups` | 会让线程/任务**自己醒来**的构件：`thread::sleep` · `time::sleep` · `recv_timeout` · `time::interval` · `Instant::now` · `Duration::from_secs` | 明着加回轮询 |
| `every_duration_use_is_registered_as_non_timer` | `Duration::from_*` 的处数必须**恰好等于**登记表条数 | 用没被列名的方式偷渡节拍（如 `from_millis(8000)`） |

**登记表不是豁免清单**：它是「这些我看过、确认不是定时器」的账，每条要写明理由
（有断言查理由非空），**多一处未登记的就红**，逼人把新的那处也想清楚。
还有一条防腐烂：登记表里的片段若已不在生产代码里，也红。

## 3. 范围写清楚，不默认扩

**只钉 daemon crate 的生产段。** monitor 侧有 UI 刷新、重连退避这类**正当**的周期行为，
把护栏扩过去会立刻变成噪音 ⇒ 要钉那半得单独论证。
**守卫范围必须等于它真正证明的性质** —— 这条在模块头注里写死了。

反向自检：断言「扫到的文件数 ≥ 5」+「命中数 == 0」，**不是**「命中数 < N」——
阈值绝不能挂在被优化的那个量上（rust-ts-boundary 的教训）。
