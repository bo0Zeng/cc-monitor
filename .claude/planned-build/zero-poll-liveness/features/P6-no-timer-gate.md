## 2. 判据落在「周期性唤醒」，不是落在「出现过 `Duration`」

**这是本护栏设计上最要紧的一点。** 先实测全 crate 生产段的 `Duration`/`Instant` 用法：

```
watcher.rs:49   use std::time::Duration;
watcher.rs:666  Duration::from_millis(DEBOUNCE_MS)
```

只有两处，而 `DEBOUNCE_MS`（100ms）是 **notify-debouncer 的事件合并窗口** ——
它**不产生唤醒**，只决定「同一批文件事件攒多久再一起交付」。去掉它 inotify 照样推事件，
只是更碎。**它是 `Duration`，但不是定时器。**

若把判据写成「不许出现 `Duration`」，就得为这一处开豁免；豁免一开，下一个人加节流常量时
顺手也塞进豁免里 —— 护栏从「防退化」变成「防不了但很吵」。

⇒ 拆成**两条互补的断言**：

| 断言 | 禁什么 | 防的是 |
|---|---|---|
| `daemon_production_code_has_no_periodic_wakeups` | 会让线程/任务**自己醒来**的构件：`thread::sleep` · `time::sleep` · `recv_timeout` · `time::interval` · `Instant::now` · `Duration::from_secs` | 明着加回轮询 |
| `every_duration_use_is_registered_as_non_timer` | `Duration::from_*` 的处数必须**恰好等于**登记表条数 | 用没被列名的方式偷渡节拍（如 `from_millis(8000)`） |

**登记表不是豁免清单**：它是「这些我看过、确认不是定时器」的账，每条要写明理由
（有断言查理由非空），**多一处未登记的就红**，逼人把新的那处也想清楚。
还有一条防腐烂：登记表里的片段若已不在生产代码里，也红。

## 3. 范围写清楚，不默认扩

**只钉 daemon crate 的生产段。** monitor 侧有 UI 刷新、重连退避这类**正当**的周期行为，
把护栏扩过去会立刻变成噪音 ⇒ 要钉那半得单独论证。
**守卫范围必须等于它真正证明的性质** —— 这条在模块头注里写死了。

反向自检：断言「扫到的文件数 ≥ 5」+「命中数 == 0」，**不是**「命中数 < N」——
阈值绝不能挂在被优化的那个量上（rust-ts-boundary 的教训）。

## 7. 第二半：端到端延迟 e2e（**已并进 `graylight-daemon-frames`**）

载体按 §1 的结论**直接并入**，没另造套件。加了 3 条断言（5 → 8）：
「新会话已进快照（差分有基线）」·「死亡帧在上限内到达」·「死亡帧点名的是被杀的那个」。

**阈值是数量级判据，不是性能指标**：上限取 **5s**。本机手工实测 126ms，但 CI runner 慢得多，
把阈值卡在实测值上只会换来随机红。它要区分的是「事件驱动（亚秒）」与「退回 8s 轮询／永不」。

**套件里报出的那个毫秒数是上界、不是精确延迟**：`wait_line` 是 0.5s 轮询 ⇒ 粒度 500ms
（本地跑出 537ms）。精确数字看 P4/P5 的手工实测，别拿这个数当性能基线。

### 7.1 ★ 撞出一个 P5 留下的真回归（**改前版本对照确认，不是本轮引入**）

并 e2e 时套件整体红了，停在第 2 段。**对照组决定性**：`git stash` 切回改前版本，
**同样红、停在同一处** ⇒ 与本轮改动无关。

根因：第 2 段杀的是**会话里的 claude 进程**，tmux 会话本身没动 ⇒ **不触发任何 hook**
⇒ **不再有新的 `tmux_sessions` 帧**。它此前能过，是因为 8s ticker 每隔一阵重发一份快照；
**P5 把 ticker 删了**。

**为什么 P5 那轮没接住**：这 6 套是 **CI-only**，不在 `cargo test` / `npm test` 里，
而 P5 的门禁扫了后两者。⇒ **删掉一个周期性信号时，光跑单元 + 集成门禁不够，
还要跑依赖那个节拍的 e2e。**

处置：把第 2 段的判据从「等一个**新** tmux 帧」改成「**最新已知**快照里仍含 `@ccm_sid`」——
那才是灰灯真正依赖的条件（monitor 侧本来就是拿 `tmux_raw_registry` 缓存的那份判的），
且不再依赖一个已被有意删除的节拍。**语义与原意一致，不是把断言放松。**

### 7.2 两个把自己绕进去的坑

| 坑 | 症状 | 处置 |
|---|---|---|
| `date +%s%3N` | 本机 `date` **不认 `%3N`**，原样吐 9 位纳秒 ⇒ 日志里那个「ms」是天文数字（`1606903500233221065ms`）。**断言照样过** —— 只有读日志的人被误导 | 改 `%s%N` 再除 1e6 |
| `set -e` 下 `V="$(cmd)"` | cmd 失败**直接中止脚本** ⇒ 下面 `bad` 里精心写的诊断永远打不出来（变异验收时只剩一个光秃秃的 rc=1） | 加 `|| true`，交给 `[ -z ]` 分支报 |

第二条是**套件里既有的写法**（第 3 段也这么写），本轮只在新增处避开，**没有顺手改既有那几处**
—— 那是另一件事，已登记。
