## 逐 issue 根因

### #75 会话拉不起来 —— 【主因=account-ux 回归 + 直连路径窗口闪退】
- **主因（两远端路径共有）**：`resolveFollowAccount = lastAccount → current → null`（`accounts.ts:167-179`）。灰会话若在账号 B/基座下建、又无 pin → resume 注入**当前账号 A** 的 configDir（`buildEnvPrefix` `remote-launch.ts:76-82`）。账号隔离 = 各账号独立数据目录 → `claude --resume <sid>` 在 A 下查不到 → 确定性失败。cwd 空/陈旧同理。
- **直连路径最凶**：`bash -lic 'cmd && claude --resume'`（`remote-launch.ts:99-104` + `launch.rs:133-140`）**无 tmux、无 keepalive**。`--resume` 一非零退出 → shell 结束 → ssh 断 → **wt.exe 标签一闪即灭**，用户看不到任何错误 = 彻底起不来。
- **tmux 路径**：`send-keys` 打进交互 shell，`--resume` 失败后回落空 bash，`attach` 把用户接进**没有 claude 的 idle shell** + 残留 `cc-<sid8>-N`。
- 次要：`list_remote_tmux` 抛错的退化分支里 `pickFreshTmuxName` 返基名 `cc-<sid8>`，若撞上孤儿 → create-gate 短路只 attach 进孤儿。`tabs.ts:1890`「退化不变砖」注释**不准确**。

### #76 tmux 命名冲突/孤儿堆积 —— 【已核实：4 套命名 + 零回收】
- `cc-*` 空间 4 套规则：① `cc-<sid8>`/`-N`（tmux resume；sid 是 UUID→前 8 位 hex=issue 的 `cc-<8hex>`）② `cc-<cwd-basename>`（新会话）③ `<project>_cc`（**cc-bus `cc-spawn` 产**，已核实是 `claudecode-frontend_cc` 来源）④ 无名（直连）。
- **孤儿成因**：tmux resume 的 `send-keys` 把 `claude --resume` 打进交互 shell，claude 退出后 **shell 仍占 `cc-<sid8>` 名**、前台变 `bash` → 下次 resume 同 sid 不精确命中 → `pickFreshTmuxName` 产 `cc-<sid8>-2/-3`。而 `tmux_reconcile.rs` 只把 tab 变灰、**从不 kill tmux**（`:10-11`）→ **零自动回收**，孤儿只增不减。
- **attach 管不了**：`<project>_cc` 无 `@ccm_sid`，而只要列表存在任一带 sid 的会话，`findClaudeTmux` 的 `anySidKnown` 判据就禁止 cwd 回退（`tabs.ts:249-250`）→ 永远匹配不到。
- **样板**：换号重启路径（`account-restart.ts:152,163`）「先 kill 同名 → 同名重建 → 带 @ccm_sid」是唯一命名+身份+回收都对的路径，可作统一标准的模板。

### #72 自建会话不设 @ccm_sid —— 【tmux 路径已修 + 测试；直连/新会话仍缺】
- 已修：`buildResumeTmuxCmd` 传完整 `ccmSid: sid`（`remote-launch.ts:147-152`）→ `createRunAttach` create 分支 `set-option @ccm_sid`（`session-backend.ts:64-71`，非阻断包裹），测试锁死（`session-backend.test.ts:64,78`、`remote-launch.test.ts:129,177,213`）。
- **残留缺口**：直连 resume（不进 tmux、无 @ccm_sid）+ 新会话 `buildLauncherCmd` 不传 ccmSid（`remote-launch.ts:206`，因新会话 sid 未知——合理但默认裸 claude 又不调 `__ccm_rbind` → 永远无 @ccm_sid）。

### #74 / #41 ↗ 拉前失败/不及时 —— 【子因1 结构性永久 + 子因2 时序】
- **子因 1（永久）**：直连用裸 claude 绕过 wrapper → `__ccm_rbind` 从不运行 → 无 `ccm-rbind-<sid>` 标题（`ccm-wrapper.sh:17,34`）→ `bring_remote_terminal_to_front` 扫不到（`lib.rs:1490-1521`, `bind.rs:642`）→ 永久「未绑定窗口」。配置耦合陷阱。
- **子因 2（时序）**：走了 wrapper，标题「远端 shell→SSH→tmux→本地 WT」四跳 + wrapper 每 1s 轮询/仅 sid 变或每 ~20s 重打（`ccm-wrapper.sh:16,27`）。已加 4s 重试（F75 `bind.rs:678-704` + `lib.rs:1512-1519`），但 **4s < 20s 重打周期** → 首点常失败、后点成功。真机微调未收敛。

### #60 带外杀会话不变灰 + attach 串会话 —— 【①机制查清、②已修 F74】
- **①（不变灰）**：`remote_active` 唯一写者 = `remote-session-emitter`（`lib.rs:537-551`）；daemon **只看 pidfile 不看 tmux**（`tmux_reconcile.rs:4-5`）。`Ctrl-b &` 杀 tmux 但 claude 被 bg-spare 托管不死 → pidfile 在 → 不发 removed → 恒 live。「又杀几个才批量变灰」= **断连 flush 批量清**（`ssh_source.rs:1714-1719`），非定期对账。**本分支已加 tmux 存活信号**（F74c `tmux_reconcile` poller `lib.rs:664-666`），但真机未验证 + 常量待标定 + daemonless 静默退化。
- **②（attach 串会话）**：老 bug 元凶 = cwd 回退绑定。**本分支已修**：`findClaudeTmux` 先 @ccm_sid 精确、无命中且有其它 sid 就返 undefined、只有整表无 sid 才 cwd 回退（`tabs.ts:242-254`）。**前提**：远端需重装 ccm 助手写 @ccm_sid。

## 统一「起会话」标准建议（回应用户「搞成同一个标准」）
以换号重启路径为模板，所有 cc-monitor 起/resume 会话收敛到：
1. **命名**：resume 用 `cc-<sid8>`；新会话在拿到真 sid 前用占位、之后由 wrapper 认领。杜绝 `cc-<cwd-basename>` 独立规则。
2. **必设 @ccm_sid**：已知 sid 的路径全经 `createRunAttach({ccmSid})`；直连 resume 应能选「进 tmux」以获身份 + 可 attach（或默认就走 tmux 版）。
3. **必经 wrapper**：默认 launcher 从裸 `claude` 收敛到调 `__ccm_rbind` 的 `ccm` 语义 → 一举同时修 rbind 标题（#74/#41）与身份建立。
4. **回收**：给 tmux resume/新会话的载荷加「claude 退出即 exit」收尾（`… && claude --resume <sid>; exit`），或让 reconcile 对 `cc-*` 命名空间内确认无 claude 的会话可选 kill（经 src-tauri，daemon 仍只读）。**当前零回收是 #76 堆积直接原因。**

## 红线核对
- **daemon 无需新 Rust 改动**：#60① 的 `tmux_reconcile` + daemon `TmuxSessions` 帧**已内嵌**（p1p），只差真机验证 + 常量标定。回收走 src-tauri 的 `kill_remote_tmux`（非 daemon）。→ **本族可在「daemon 零改」红线内做**。
- **唯一外部依赖**：@ccm_sid 信号质量依赖**远端重装 ccm 助手**（用户机器动作，非代码）。
- **双写点警告**：`TMUX_LS_FMT`（`tmux.rs:22` ↔ `watcher.rs:69`）任一侧改列会静默丢行 → @ccm_sid 全废、回退老 bug。本族不改它。
