## 1. 开工复测：计划里的命令数是**旧的**，而且天真的数法会数出三种不同的答案

主计划 §1 L5 写「枚举全部 **119** 个 Tauri 命令」。实测：

| 数法 | 结果 | 这个数字是什么 |
|---|---|---|
| 主计划记的 | 119 | **过时**（写下时的值） |
| `grep -c '#\[tauri::command\]'` | **127** | **错**——见下 |
| 剥掉注释后的属性行 | 121 | 接近，但仍多一个 |
| **`generate_handler!` 里的条目** | **120** | ✅ **这个才是「前端能调到的命令」** |
| 剥注释后按**函数名去重** | **120** | ✅ 与上一行**对上了** |

**对账结果：120 = 120，未登记 0 条，登记了但无属性 0 条。** 今天是干净的。

### 1.1 那 7 个差额是什么——**其中 6 个是「扫源码守卫」的经典陷阱**

`127 → 120` 拆开：

| 差额 | 数量 | 成因 |
|---|---|---|
| **散文里逐字提到 `#[tauri::command]`** | **5** | `hooks_diag.rs:501,937` · `ssh_source.rs:14,3239` · `tmux.rs:122` —— 都是在解释「这段藏在 `#[tauri::command]` 里所以单测碰不到」 |
| **文档注释制造的假阳性函数** | **1** | `history.rs:987-989`：doc 注释里写了 `#[tauri::command]`，紧接着下一行就是 `fn build_resume_ps_command` ⇒ 天真的正则把这个**私有 helper** 认成了命令 |
| **同名的平台 cfg 变体** | **1** | `bring_monitor_to_front` 在 `lib.rs` 里有两份（`#[cfg(windows)]` / 非 windows），**一个逻辑命令、两份实现** |

**★ 第二行是我自己当场踩进去的**：做这个复测时第一版正则就报了「`build_resume_ps_command`
带属性却没登记」——看起来像个真发现（漏注册 = 运行时 `command not found`、**不是编译错**，
`ssh_source.rs:3239` 的注释专门警告过这一点）。**去看定义才发现那行根本没有属性。**

⇒ **对 L5 的直接约束**（写进实现，不是写完再说）：

1. **数之前先剥注释** —— 否则光散文就多 5 个。这与 P4/P6 那七次自指陷阱**同族**：
   扫源码的守卫必须先把「代码」和「关于代码的话」分开。
2. **按函数名去重，不按属性出现次数计** —— 平台 cfg 变体是一个命令。
3. **以 `generate_handler!` 为准，而不是以属性为准** —— 属性只说「它能当命令」，
   `generate_handler!` 才说「前端真能调到」。**两者对不上本身就该是一条断言**
   （今天差 0，正好可以钉死在 0）。
4. **数完先确认数的是不是那个东西**（本区第一次应用这条，来自 `zero-poll-liveness` P5）。

## 2. 判据：**声明能力，让机器算对称** —— 而不是从代码猜

§40 的 120 条命令看完之后（先看形状再定判据，P6 的教训），判据这样落：

| 层 | 为什么不用它 |
|---|---|
| 命令名带 `remote` | **表面特征**。27 条，漏掉 10 条真远端命令（`cc_bus_*` · `tmux_send_keys` · `account_usage` · `probe_ccm_cli` · `check_account_trust` · `resolve_ssh_host`） |
| 吃 `origin` / host 参数 | 也是表面特征。25 条，漏掉 12 条 —— 它们吃 `RemoteConfig` 结构体，或干脆不吃参数（`aggregate_remote_usage_all` 这类是「枚举所有远端」） |
| **每条命令声明「属于哪个能力 + 服务哪一侧」** | ✅ 采用 |

真正要回答的是「**这项能力在两侧都有吗**」，而那是判断、推不出来
（本地需不需要 SFTP 面板？不需要 —— 但没有任何语法能说明这一点）。

**关键的一步：对称与否由机器算，不由人声明。** `config_surface.rs` 里留着 T04 审计的教训 ——
一个能由别的字段 1:1 推出来的声明字段就是**安慰剂**。这里人只声明 `(命令, 能力, 哪一侧)`，
「对称/不对称」是算出来的；人只需要为**算出来的**不对称写理由。

## 3. 落地：`src-tauri/src/parity_ledger.rs`（整体 `#[cfg(test)]`）

范式照 `config_surface.rs::every_host_declaration_is_pinned`（T02）：钉死表 + `assert_eq!` 计数。
**没有复用 `structural_scan`** —— 它是给 shell 文本用的「标记 + 窗口」扫描器，
本表的判据是**声明表上的集合相等**，形状不合；计划点名的也是 T02。

**实测形状**：120 条命令 → **50 个能力**（29 对称 / **21 不对称**）；
Local 45 · Remote 54 · Both 21。

### 3.1 四条断言的分工

| # | 断言 | 防什么 |
|---|---|---|
| 1 | `generate_handler!` ↔ 本表**双向相等** | 新增命令不登记就红（§40 点名要的那条）；删了命令不清表也红 |
| 2 | 算出的不对称集合 **==** 理由表键集合 | 多一个不对称没写理由会红；**补齐两侧后理由还留着也红**（防表腐烂） |
| 3 | 声明 `Local`/`Both` 的命令，签名里**不许**有远端专用参数 | 「为了让表好看，把远端命令声明成两侧都有」 |
| 4 | 表的形状（120 / 50 / 21 / 7·12·2）钉死 | 静默缩水 |

**反向那条刻意没做**（`Remote` ⇒ 必须吃远端参数）：实测有 **11 条合法例外**
（枚举全部远端的、按 id 查应用侧缓存的、`sftp_cancel_transfer` 拿 `transfer_id` 的），
加进来是「11 条豁免表换一条几乎不设防的断言」。**而且它防的方向无害** ——
把本地命令误报成远端只会多出一条要写理由的**假欠账**，不会造出**假的平价**。
有牙的是第 3 条那个方向，今天实测 **0 违规**，就钉在 0。

### 3.2 `Undecided` 是刻意留的第三类

理由分三种：`NaturallyAsymmetric`（本地**不需要**）· `ParityDebt`（该有没有）·
**`Undecided`（本表新发现，需要产品判断）**。
留第三类是因为：把没人裁定过的缺口塞进白名单，等于**用门禁给自己发豁免**。

## 4. 结果：21 项不对称，其中 **2 项是本表交出的新发现**

**天然不对称 7 项**（`§40` 白名单 4 条 + 3 条本轮补齐）：
`sftp.file-panel` · `port-forward` · `daemon.deploy` · `ssh.host-config`（本地按定义就是「不走 ssh」）·

**平价欠账 12 项**：`accounts.list` / `.session-accounts` / `.trust` · `usage.per-account` ·
`acct-iso.check` / `.shellinit`（六项归 **L3**）· `tmux.manage`（归 L1/L2）·
`audit.config-surface`（§40 已记的反向缺口）· `history.branch` ·
**`cc-bus.cockpit`** · **`session.tasks`** · **`subagent.load`**。

后三项值得单说 —— 都是**实测**出来的，不是照抄记录：

| 欠账 | 实测依据 |
|---|---|
| `cc-bus.cockpit` | `cc_bus.rs` 的 5 个 IPC **全走 origin+ssh、零本机读取路径**（`config_surface.rs` 的钉死表已把 `~/.cc-bus/` 记为 Remote）。而本机 cc-bus 是存在的 —— `diagnose_local_cc_bus_hooks` 就在诊断它 ⇒ **驾驶舱管不了本机的 agent** |
| `session.tasks` | `get_session_tasks` → `tasks_root_for_current_claude_dir()` → `paths::resolve_claude_dir()`，读的是**本机**目录 ⇒ **远端 tab 拿不到任务列表** |
| `subagent.load` | `load_subagent` 拿 `parent_jsonl_path` 建 `PathBuf` 并 `is_dir()`，读**本机**文件系统 ⇒ **远端会话的 subagent 展不开** |

**未裁定 2 项（本表的主要产出）**：

- **`panorama.code-graph`（21 条命令，最大一块）** —— 全部只吃本机 `repo` 路径。
  远端 repo 的代码图谱**既没做、也没在任何计划里登记过**。
  **不擅自判它天然不对称** —— 那需要产品判断（远端开发是不是本工具的场景）。
- **`ccm.install-ui`** —— 本机安装向导有「扫 PATH 选装到哪」+「预览要写的文本」两步；
  远端 `install_remote_ccm_helper(cfg, profile)` 一步到位、没有这两步。是欠账还是刻意简化，待裁定。

## 5. 变异验收（Phase D）

| 变异 | 结果 |
|---|---|
| **A** 漏登记一条已注册命令 | **成立**：断言 1 精确点名 `["save_config"]`（断言 4 计数一并红） |
| **B** 把吃 `origin` 的远端命令谎报成 `Both` | **成立且隔离**：**只红断言 3**，报「声明为 Both，签名里却有远端专用参数 `origin:`」 |
| **C** 某项不对称没写理由 | **成立且隔离**：**只红断言 2**，点名 `["history.branch"]` |
| **D** 补齐两侧后理由还留着（表腐烂） | **成立**：断言 2 报 `["sftp.file-panel"]`（断言 3/4 计数一并红） |
| **E** **护栏自身失效**（签名采集器扫不到文件） | **成立**：断言 3 报「检到 **0** 条（真实应为 66）」⇒ 反向自检有效 |

> **★ 一次差点写进记录的假读数**：跑变异时用 `cp -a` 恢复原文件 —— **`cp -a` 保 mtime**
> ⇒ cargo **不重编**，接下来那次 `cargo test` 读的是**上一个变异的旧二进制**。
> 这条坑我自己的方法论里就记着（SS-10 同步 vendored 时踩过），这次换了个场景又踩。
> **恢复后必须 `touch`**，且判色前先跑一次「恢复态应全绿」确认基线回来了。
> 变异 C 的锚点还同时没匹配上（`cargo fmt` 重排过），两件事叠在一起就是一条完全虚假的红。
> 修法：锚点带显式处数断言（`assert count == 1`）+ 恢复即 `touch` + 恢复后先验绿。

**如实标注**：铁律 8 要求并行多 agent 审计；本会话常驻指令「除非用户要求不开 agent」
⇒ 主线程变异 + 全门禁代替。**这是欠账，不是强度裁剪。**
