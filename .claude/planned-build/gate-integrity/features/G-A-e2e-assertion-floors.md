## 3. `cc-spawn-uplift` 此前**不打印断言数**，而且藏着一条手搓判定

STATUS 说「`cc-spawn-uplift` 没打印、要先加」—— **这条计划是对的**（本区少见）。
加计数时又撞出一件计划没提的：

```
实测输出 21 行 PASS，而新加的计数只到 20
```

差的那一条是**手搓的**：

```bash
if [ $((e-s)) -lt 15 ]; then echo "  PASS 未挂起（$((e-s))s）"; else
  echo "  FAIL 耗时 $((e-s))s，疑似挂在 attach"; fail=$((fail+1)); fi
```

它绕开了 `chk`，于是**既不进计数、也不在门禁的账里**。改成走 `chk` 后 20 → 21 对上。
（这正是「静态 `chk` 调用数 ≠ 运行期断言数」的另一面：本套件静态 `^chk ` 是 20、运行期 21。
**用实测值**。）

## 4. 做了什么

### 4.1 `e2e/assert-pass-floor.sh`：一个可复用的度量器

`bash e2e/assert-pass-floor.sh <npm-script-后缀> <地板>` —— 跑套件、抓收尾那行
`===== 合计 PASS=<n> FAIL=<m> =====`（8 套逐字一致的格式）、比地板。

**fail-closed 三条**：
1. 套件本身非零退出 ⇒ 失败（输出原样透传）
2. **抓不到 `合计 PASS=<n>` ⇒ 失败**，不当作 0 也不当作通过。抓不到只有两种可能——
   套件被改得不打印了，或它压根没跑到收尾，**两种都该红**
3. `n < 地板` ⇒ 失败，诊断同时给实得与地板

**别写成 `npm run … | tee`**：管线会把 npm 的退出码藏起来。落文件再回显。

### 4.2 地板值写在**调用处**（`ci.yml`），不写在脚本里

脚本对「哪套该有多少条」一无所知，它只是度量器。地板与套件的对应关系是 CI 的知识
⇒ 写在调用行上，**改地板时一定会在 diff 里看见**。

（与 G-B 相反：那边地板写在 vendored `run-tests.sh` 自己里，因为 SS-10 不许改副本。
这里没有那个约束，所以按「改动可见性」选调用处。）

### 4.3 ★ 顺手消掉一个已经漂过两次的双写点

8 个 CI 步骤的名字原先都带条数（`tmux 目标精确匹配（F01，26 项）`）。
STATUS 记着这些标签**漂过两次**（39 vs 44、12 vs 21）。

标签里的数与地板是**同一个数的第二处字面量**，而地板那处是被**强制**的。
⇒ **把标签里的「N 项」去掉**，留地板一处。这不是加守卫去钉两处一致，是**把第二处消掉**
（同 Z03 提 `UNSET_CONFIG_DIR_PREFIX` 的思路：双写点在能消掉的时候就消掉）。

### 4.4 覆盖面地板：少接一套照样绿，这才是本功能在治的病

新增 `e2e-smoke` 一步，两层校验：

1. `run: bash e2e/assert-pass-floor.sh` 的**出现次数 ≥ 8** —— 防「某步被改回裸
   `npm run test:X`」或整步删掉
2. **逐对校验**「套件名 + 地板值」八对都在 —— 防地板被抹成 0（那种改动过不了第 1 条的计数，
   却能过宽松的模式匹配）

**计数模式必须精确到 `run: bash e2e/…`**：本步骤自己那几行 grep 也含脚本名，
用宽模式会把它们算进来（**实测会数成 11 而不是 8** —— 那个数就成了假的）。
