# devsched 的配置

`devsched [--local] [--config <目录>] [--] <命令…>`，在要编的那棵树里任一处起。准备一台：`devsched [--config <目录>] --prepare <台>`（见「工具清单」）。

配置目录：`--config <目录>` ＞ `DEVSCHED_CONFIG` ＞ `~/.config/devsched/`。里面两样：

```text
<配置目录>/hosts                 主机表
<配置目录>/projects/<项目>.conf  项目配置（文件名去掉 .conf 就是项目名）
```

认不得的键照留、不报错。下面标「这一版不用」的键，devsched 读进来但不照它做（打算的用法写在后面，留着给以后）。

## 主机表 `hosts`

一台一行：`名 位数 去法 选项…`，`#` 起头（前面可以有空白）是注释，空行跳过。行序就是挑的先后。位数不是数、去法认不得的那一行跳过。主机表每一圈重读，改它不用重起。

| 列 | 值域 | 用途 |
|---|---|---|
| 名 | 一个词 | 日志、冷却、位锁都按它记 |
| 位数 | 非负整数 | 同一时刻最多几趟；0 ＝ 不派 |
| 去法 | `local` · `ssh:<ssh 名>` | `local` 是本机那一行；`ssh:<名>` 经 `ssh <名> <base>/state/devsched-node --root <base>` 连编译节点 |

选项写成 `键=值`，空白分隔。门槛写成 `放行/停`（只写一个数 ⇒ 两个都是它）：

| 键 | 值域 · 单位 | 默认 | 用途 |
|---|---|---|---|
| `mem` | G/G | 不看 | 可用内存：派之前 ≥ 放行（只管第 2 个位起）；跑着 < 停 ⇒ 停作业 |
| `psi` | %/% | 不看 | 内存压力（some avg10）：派之前 < 放行；跑着 ≥ 停 ⇒ 停作业 |
| `tmp` | G/G | 不看 | `/tmp` 剩余：派之前 ≥ 放行（停线这一版不带） |
| `disk` | G/G | 不看 | 节点根目录所在盘剩余：派之前 ≥ 放行；跑着 < 停 ⇒ 停作业 |
| `threads` | 个/个 | 不看 | 整账号线程数：派之前「现数 − 我们的 ＋（在跑趟数 ＋ 1）× peak」≤ 放行（停线由节点自己的余量管） |
| `peak` | 个 | 60 | 一趟预计吃多少线程（给 `threads` 算） |
| `base` | 绝对路径 | 无（远端必写） | 节点的登记根：节点在 `<base>/state/devsched-node`，树在 `<base>/projects/<项目>/<树名>`。长度有上限：`<base>/t/xxxx` 再接 80 字节的 socket 后缀要 < 108 字节，根最多约 21 字节（如 `~/dsrs`，家目录展开后算）；超了节点拒、调度端当场说「根太长，不派」。根在家目录下时，那台家目录里的 `.cargo/config.toml`（rustc-wrapper · incremental 之类）会被作业里的 cargo 读到：接受、不隔断，节点 hello 的 `cargo_config` 照实报、调度端记进日志。不要跟别的东西共用一个根 |
| `nice` | 整数 | 不带 | 作业帧带过去的 nice |
| `trust` | `own` | 不可信 | `trust=own` ⇒ 自家机器；`need_own` 的作业只派可信机器（这一版另限只本机） |
| `fallback` | 分钟 | 不写 ⇒ 本机就是排在后面的一台 | 只本机那一行：写了 ⇒ 本机的位只给只本机的作业，远端全都接不到或冷着连着这么久，能出本机的才回本机 |
| `timeout_s` | 秒 | 7200 | 整趟时限（从交出作业起）：到点停作业整组收、退 124、不冷那台；项目配置里写的 `timeout_s` 优先 |
| `caps` | 能力,… | — | 这一版不用：能力由节点在 hello 里自己报（cargo · tmux · tmuxnew · node · gui · jdk · android · rsync），调度端记在状态目录 `caps/<台>` |
| `tc` · `tool` · `jobs` · `tthreads` · `sccache` · `path` | — | — | 这一版不用：工具链、缓存、并发封顶都归节点（`<base>/toolchains` · `cache/`） |
| `trees` | 个 | 10 | 那台上每个项目留几个远端编译树（`<base>/projects/<项目>/` 下的目录：树与树外产物目录 `target-*` 一起数；镜像 `mirror`、兄弟仓 · 只读附带、`.` 起头的不算）。只按个数删，不为盘删（盘只由 `disk` 门槛与停线管）：每趟连上、过门槛之前，过了它就从最久没用的起叫节点删（`clean`：节点当场改名进 `.del-*`、另起线程删），一个一个删到不超为止，一趟最多 4 个；这一趟的树与它的产物目录、一趟时限之内用过的（可能正被别的趟送着）、有作业在跑的不删；都是刚用过的删不动时记一行。删了当场对一遍镜像（见 `mirror`）。最久没用照本机状态目录 `used/<台>/<项目>/<名>` 的修改时刻（每趟一连上就记，树与产物目录一起记），没记过的当最久没用——所以只该有这一台调度端往编译机派：别处送的在这里永远是「没记过」。本机那一行不删（本机的树是用户的工作树） |
| `maxrun` · `maxbuild` | — | — | 这一版不用：不按时长删；按个数删见 `trees` |
| `slurm` | srun 参数，逗号分隔（如 `-p,cpu,-c,64,--mem=128G`） | 不写 ⇒ 不经 slurm | 共享集群上编译不许跑在登录节点：ssh 命令给节点加 `--slurm <那一串>`，节点当上主节点时把自己换成 `srun --ntasks=1 <参数…> <节点> …`，在分到的那一份里管作业；已有主节点时只当转发、不另起 srun。那台所有的位共用这一份分配，核数 · 内存按整台同时跑的全部趟写；节点没连接就退，分配跟着还 |
| `locks` | — | — | 这一版不用：位锁一律 `<状态目录>/slots/<台>.<序号>` |
| `small` | — | — | 这一版不用 |
| `wbudget` · `wdev` | — | — | 这一版不用：写盘预算没做 |

## 项目配置 `projects/<项目>.conf`

一行 `键 = 值`（等号后面至多吃掉一个空白，行尾空白去掉），键是小写字母 · 数字 · 下划线；别的行跳过。

**树根**：从当前目录往上，照项目文件名的先后，头一个找得到 `marker` 的项目，取离当前目录最近的那一层；任意路径。认不出项目 ⇒ 这一趟只本机。树名 ＝ 树根路径摘要前 8 位（跨趟不变；远端树路径长度不跟本机树根末段走，调度记录里那一列另带末段：`<末段>-<树名>`）。

**正则**一律当 regex 原样用（`[[:space:]]` 这类写法照认），匹配的对象是「`/<树里的相对目录>` ＋ 空格 ＋ 整条命令（参数以空格连起）＋ 空格」；树根上起的，相对目录那一截是空的。除这几个之外不从命令文字里猜。

| 键 | 值域 | 默认 | 用途 |
|---|---|---|---|
| `marker` | 相对树根的路径 | 必写 | 认这个项目 |
| `hosts` | 台名… | 空 ＝ 主机表里的远端都能派 | 写了 ⇒ 这个项目的趟只派这几台远端（本机照旧）；源码只许出到哪几台由它限 |
| `remote_if` | 正则 | 空 ＝ 都能出本机 | 不合它的只本机 |
| `local_if` | 正则 | 空 | 合它的只本机 |
| `need_<能力>` | 正则 | 空 | 合它的这一趟要那项能力（能力名跟节点 hello 报的逐字对）。跑 cargo 的项目要写 `need_cargo`（如 `(^|[[:space:]/])cargo[[:space:]]`）：节点只认根下 `toolchains/` 里的 Rust 工具链，没装好的那台不报 cargo、不派；不写就可能派去没工具链的机器、退 127 |
| `need_own` | 正则 | 空 | 合它的会产出进仓文件：只派可信机器，这一版只本机（不拉回文件）。不是一项能力 |
| `heavy_if` | 正则 | 空 | 本机重活：只本机、只拿本机第 1 个位 |
| `heavy_prefix` | 一串词 | 空 | 重活前面原样加的（按空白拆成数组，如 `nice -n 19 ionice -c3 env GRADLE_OPTS=…`） |
| `prio_env` | 变量名 | 空 | 这个变量 = 1 ⇒ 排在普通号前面（`DEVSCHED_PRIO=1` 恒认） |
| `local_env` | 变量名 | 空 | 这个变量 = 1 ⇒ 只本机（同 `--local`） |
| `timeout_s` | 秒 | 主机表那一行的，再没有 7200 | 这个项目每趟的整趟时限，盖过主机表；到点停作业、退 124。不另设「多久没输出」（cargo test 有正当的长时间静默） |
| `exclude` | 一串模式 | 空 | 排除清单：原样当模式（不做路径展开），另有删不掉的内置一组；送出清单照它产出（见 `devsched-policy`） |
| `build` | 树里的相对目录 | 空 | 产物目录：同一个同一时刻只一趟（调用方给了 `CARGO_TARGET_DIR` 就按那个） |
| `env` | 变量名… | 空 | 带去远端的：调用方此刻设着的照带（空值照带，空 ＝ 不要）；调度自己只在 `sccache = 0` 时设一个 `RUSTC_WRAPPER=`（见下），别的一个都不加。指向程序的（RUSTC_WRAPPER 等包装类）那台没有就摘掉并说一句；RUSTC · CC 等只说一句 |
| `data` | 树外目录… | 空 | 只读附带：照树根一样送（文件去掉写权限），路径照样改写 |
| `siblings` | 树外目录… | 空 | 兄弟仓：照树根一样送，路径照样改写 |
| `rsync` | — | — | 这一版不用：送源码固定按内容比、不带 mtime（`-lpD -c`）。两头的 rsync 都要 ≥ 3.1.0（用 `--delete-missing-args`；目的目录由 `--rsync-path=mkdir -p '<目的目录>' && rsync` 在远端先建，不用 `--mkpath`）：编译机那头由节点探，版本够才报能力 `rsync`，派远端的趟一律要它、不够的那台不派；开发机这头不探，上线时核。远端登录 shell 要是 POSIX 的 |
| `local_sh` · `sh_ok` | — | — | 这一版不用：不从命令里认 `.sh` |
| `git` | `1` | 不写 ⇒ 远端树里没有 git | `1` ⇒ 远端树带上 git，要问 git「改了哪些」的命令（快检挑段）在远端答得跟本机一样。树根是 git 顶层时才做，不是就照旧只送源码。送源码前本机把索引照原样写成一个提交（带上已 add 未提交的；提交人固定 `devsched`），连同 HEAD（所在分支）· `main` · `origin/main` · 上游 `git push --force --no-verify` 进那台的镜像（见 `mirror`）；源码照旧 rsync，之后一下 ssh 写镜像里这棵树的工作树记录（`worktrees/<树名>/`）、远端树的 `.git` 指针、读进索引并刷新。分支有上游 ⇒ 镜像里只写 `branch.<分支>.remote = .` 与 `merge = <上游的完整引用名>`。同步之后远端树 ＝ 本机树：跟踪的照本机（远端作业改过的写回），远端「没跟踪又没忽略的」里本机没有的删掉，`.gitignore` 里的（产物 · 缓存）不碰。**推过去的只有这几个引用指着的提交**（连同它们的全部历史，作者名邮箱照提交原样）：stash · notes · tag · 别的引用 · 钩子 · 本机 `.git/config`（身份 · remote 地址 · 别的配置）一样不推。排除清单不过滤历史，所以只给本来就公开的仓写 `git = 1`；索引里有排除清单点到的路径 ⇒ 不推、这一趟只本机。不可信的机器（别人有 root）能读到推过去的全部历史。远端要有 git 与 `flock`；推不进 · 记不成算那台的（冷、回队里）。头一回推进一台带整段历史（这个仓约 300 MB），慢链路上要几十分钟：推的整趟时限 3 小时（送目录的是 30 分钟），推一半断了下回从头推 |
| `mirror` | 相对路径 | `_mirror.git` | 那台上的镜像：`<base>/projects/<项目>/<mirror>`（不许绝对、不许 `..`）。同一个项目各棵树共用一份，推与写记录经 `<镜像>.lock` 一次一个；没有就当场建。节点不碰它；调度端只动它自己写的（镜像 · `refs/qc/<树名>/*` · `worktrees/<树名>/` · 远端树的 `.git`）。树已不在的那几棵（删了的 · 手动删的）的 `refs/qc/<树名>/*` 与 `worktrees/<树名>/` 在对镜像时删：这一趟删了树当场对，否则一台一项目一天一回（记在状态目录 `swept/<台>/<项目>`）；推的那一下先建好树目录，引用一写目录必在 |
| `seed` · `sync` | — | — | 这一版不用：不从公开仓先拉，源码只照清单 rsync |
| `pull` · `pulldirs` · `out_env` | — | — | 这一版不用：不拉回文件，只回输出与退出码 |
| `sccache` | `0` | 不写 ⇒ 要不要 sccache 由调用方的 `RUSTC_WRAPPER` 与那台的 cargo 配置定 | `0` ⇒ 这个项目一律不经 sccache：远端与本机两支都把作业的 `RUSTC_WRAPPER` 设成空（cargo 认空为不用包装，盖过调用方设的、也盖过那台 `~/.cargo/config.toml` 的 rustc-wrapper）。给不用 sccache 是正确性问题的项目（编进 `env!("CARGO_MANIFEST_DIR")` 一类路径的产物进共享缓存会写坏别的树） |
| `tools` | 树里的相对路径 | 空 ＝ 不准备 | 这个项目的工具清单（见下）；`--prepare <台>` 照它装 |

## 工具清单

项目自己的一份文件（如 `.devsched/tools`），进仓、可审：一行一份档 `<工具名> <url> <sha256> [strip=N]`，`#` 起头是注释；同名的几行装进同一个目录。调度不认识任何具体工具，装什么全写在这里。

- 档按 url 后缀认：`.conda`（conda-forge 的包：zip 里 `pkg-*.tar.zst` 解进去；`info/has_prefix` 点到的文件照 conda 的办法把构建时的占位前缀换成那台的真前缀 `<base>/toolchains/<工具名>`，文本照换，二进制在原字符串里换、末尾补 NUL 保长度）· `.tar.gz` · `.tgz` · `.tar.xz` · `.tar.bz2`（`strip=N` 去掉前 N 层目录）。
- 工具名：小写字母 · 数字 · `.` `_` `-`；`cargo` · `rustup` · `android-sdk` 根下另有用处，不许用。
- `devsched --prepare <台>`（在树里起）：每份档在本机下载进状态目录 `tools/dl/<sha256>`（在就不再下）、`sha256sum` 核对，不对 ⇒ 这一样不装、照实说；解包与换前缀在本机的暂存目录 `tools/<台>/<工具名>/`（里面一份 `.devsched-tool` 记清单那几行与前缀的摘要，没变就不重做）；再 `rsync -a -c --delete` 送进那台的 `<base>/toolchains/<工具名>/`。本机只解包不运行下到的东西；真跑只在那台（节点 hello 探能力 · 作业）。只动那一个目录：不要 root，不碰系统 · 那台用户的家目录与 PATH；撤 ＝ 删那个目录。装完删掉 `caps/<台>`，下一趟重新 hello 收能力。退出：全装上 0，有一样没成 1，用法 · 配置不对 2。同一台同一时刻只一个（状态目录 `tools/<台>.lock`）。
- 节点：作业与探测的 PATH 是 `toolchains/cargo/bin`、各 `toolchains/<工具名>/bin`（按名字排）、节点本来的 PATH；能力照旧由 hello 探（装上 tmux ≥ 3.2 就报 tmuxnew）。本机要有 `curl` · `sha256sum` · `tar` · `unzip` · `zstd`；那台只要 rsync。

## 状态目录

```text
q/<纳秒时刻>.<pid>   一趟一个号（prio · local · needs <能力…>）；死 pid 的号谁看见谁清
slots/<台>.<序号>    位锁（flock）
target/<摘要>        产物目录锁（flock）
cool/<台>            冷到何时（unix 秒）
caps/<台>            那台上次 hello 报的能力（10 分钟作废，作废了照旧连一次重新收）
sent/<摘要>          上一趟送过的清单（下一趟据此让对面删本机已删的文件）
git/index.<pid>      git = 1 时本机索引的临时拷贝（写成提交就删）
tools/dl/<sha256>    --prepare 下到的档（核过 sha256）
tools/<台>/<工具名>/  --prepare 解好 · 换好前缀、要送去那台的那一份
tools/<台>.lock      同一台同一时刻只一个 --prepare
log/devsched.log     一趟一行：时刻 · 台 · 项目 · 树 · 结果
log/<号>.<台>.raw    远端输出原文（没改回本机路径的那一份，标准输出与标准错误混在一起）；总量过 50 MB 每趟从最旧的删
```

## 退出

作业跑完 ⇒ 命令自己的退出码。调度自己收尾一律在标准错误末尾印一行 `[devsched] <类>：…`：78 本机准备不成 · 79 命令退 0 而有跳过的段（前面逐段印「没跑：<段>」）· 124 超时（排队过了时限，或整趟跑过了 `timeout_s`）· 2 用法或配置不对。交出作业那一下印一行 `[devsched 途中] → <台>`（本机那一支带「（本机）」；换台重排的每一趟各一行）。途中的说明（派到哪台 · 换台 · 摘掉的变量 · 正则写坏了）一律以 `[devsched 途中]` 起头，不会被当成收尾那一行。本机那一支命令不存在 · 不能执行照 shell 退 127 · 126。

失败三类各记一行：本机准备没成（不冷那台，这一趟改只本机）· 远端连接不成 / 半路断 / 心跳断 / 协议指纹不同（冷那台 5 分钟、回队里）· 远端跑红（命令自己的退出码）。节点报的停因：撞停线 · 线程上限 ⇒ 回队里、冷 60 秒；起不了进程 ⇒ 冷 5 分钟；临时目录路径超长 ⇒ 这一趟不再派那台、不冷。门槛没放行 ⇒ 那台冷 30 秒（免得每圈重连）。
